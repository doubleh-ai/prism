# Prism v0.20.0 整体演进与上线方案

方案日期：2026-10-21（Asia/Shanghai）。负责人：本次协作中的 Codex。执行方式：先完成本设计、风险和验收合同，再连续开发、验证、发布、验收；不以拆出的子任务或草稿 PR 作为最终交付。

## 1. 目标、授权和完成定义

目标是把 Prism 从若干松散页面演进成一个可追溯的研究工作台：用户在对话中提出问题，Agent 调用受控平台能力；过程、原始资料、判断和任务均可回看；能力页面与对话打开同一条记录。网页报告是主载体，PDF 是指定版本的可选导出，不再是研究的强制终点。

用户已授权总体设计、独立分支开发、隔离验证、推送、审查、演进和上线，并要求可视化监督与紧急介入。常规实现取舍、修复和兼容的程序回退由执行者负责。需要用户在 Mac 输入密码/解锁认证时说明具体步骤；涉及删除有效用户数据、恢复旧数据库而丢失新写入、购买付费服务或新增外部凭证授权时单独说明实际影响。不会按每个小步骤反复索要批准。

以下全部成立才算完成 v0.20.0：

1. 本方案列出的报告隔离与任务串线问题修复，并通过真实页面和双用户测试。
2. 一条完整研究能展示真实观察时点、数据所属时点、逐项出处、推断/缺口及产业传导机制；不把链接数量当可信度。
3. 同一会话可完成指标、扫描、分析/深研、追问、保存，跳转打开原任务，不默默重跑。
4. 390/696/1440 宽度与浅深色能完成核心旅程，长内容、失败、断线、历史和重启恢复都可用。
5. 固定提交通过隔离测试、依赖审计、敏感信息审查和预发布演练；同一候选具备完整文件摘要与来源证明。
6. 发布前再次核对生产漂移、在线写入、完整备份、旧版本和兼容性；通过独立于 Prism 的可观察执行器上线。
7. 实际服务返回该完整提交；登录、研究、行情、历史回看与权限核验通过；有真实发布记录和恢复证据。CI 绿色、HTTP 200、配置存在均不能代替这些条件。

若某一媒体或外部引擎缺授权/不可用，产品明确展示“未接入/暂不可用”和影响范围，其他能力继续工作。不能伪造已连接、内容、进度或研究结果来满足验收。

## 3. 核心产品和界面设计

统一布局为左侧研究与能力导航、中央当前工作区、按需展开的右侧证据/任务详情。对话是默认入口；行情、指标与选股、分析、深研、产业链、报告保留专用视图；管理和发布只对管理员显示。

- 新研究首页只保留问题输入、近期研究、进行中任务和几个真实示例，不用大量指标卡制造信息密度。
- 每个回复区分正文、工具调用、等待用户、结果、部分完成和错误；推理片段不当正式结论；失败可恢复原任务，不自动重复付费调用。
- 工具结果卡显示对象、条件、周期、数据截至时间、状态和“查看原结果”；页面显示来源会话并可返回。
- 报告使用研究边界、核心判断、数字与计算、产业机制、反方/失效条件、缺口六类内容。每项可展开原文定位，旧版本仍可打开。
- 图谱先展示产品/工艺层次和明确的研究问题，点击关系查看业务阶段、时间、证据与反证；背景结构、已披露关系和推断使用文字及线型区分。
- 使用现有字体与图标体系、安静的中性色和单一强调色，统一留白、输入、状态、抽屉、空态和错误；深色文本实际对比度达标。手机优先保留输入、当前结果和操作，辅助内容按需展开。

## 5. 研究、来源与时间合同

新增兼容的研究账本，不把旧输出追认成已核验事实。

| 对象 | 必要信息 |
|---|---|
| ResearchRun | owner、conv、稳定 run_id、问题/实体、as_of、Asia/Shanghai、请求期间、attempt、状态、预算和缺口 |
| SourceDocument | 原发布方、原始/最终安全 URL、标题、文档号、来源类型、获取方式、获取时点、发布日期与精度/依据、数据期间、内容摘要 hash、版本/更正关系 |
| EvidencePassage | 文档 ID、页/节/表/文本定位、许可内短摘录、摘要 hash、提取结果；不因搜索摘要存在就当全文已取得 |
| Claim | 事实/计算/推断/假设、表述、实体、期间、数值/单位/币种/口径、支持/反驳/背景证据、公式和输入、限制与状态 |
| IndustryRelation | 两端实体、产品/工艺、关系类型、业务阶段、有效期间、支持和反方 Claim、传导机制与失效条件 |
| ReportRevision | schema、run、固定版本、内容块、Claim/Evidence 链接、验收状态、未解决缺口 |

研究状态为 `queued → discovering → collecting → extracting → checking → synthesizing → completed / partial / failed / cancelled`，只展示实际发生的阶段，不估算完成百分比。每轮观察时间冻结；发布日期、事件日、财报期间、行情交易时间、获取时间互不替代。只有日期就保留日精度，缺失就是未知。历史时点研究不使用之后披露的信息而不加说明。

服务端验证引用 ID、owner/run、原文是否实际取得、引用定位、日期、数值单位和计算输入。它只能证明出处和结构一致，不能声称自动证明全部语义；未经过原文支持检查的模型结论标为待核验。没有证据的供货关系、置信度、客户名和目标价不能自动补齐。三个转载页面归为同一原稿，不算三份独立证据。

Chat 的成功工具结果进入本轮账本；WebSearch 是发现线索，WebFetch 只有实际返回内容的能力范围，不能虚构 HTTP/最终 URL 元数据。Astock、Vibe、旧报告和种子图是研究输入；取得原始材料和定位后才可进入事实层。网页文本一律作为数据，不能指挥平台修改配置或扩大权限。

来源顺序为交易所/公告原文、公司 IR、可靠新闻线索与交叉对照。财联社、金十、新浪按官方可用/授权渠道接入，未授权或规则未知不启用持续批量采集，不绕过登录、验证码、付费或403。来源状态展示可用、未配置、受限、失败和最后核查时间；无需付费媒体才能运行基本研究。公司身份/代码和域名映射需核对。

公开规则核查参考：上交所 https://www.sse.com.cn/home/legal/ ，巨潮官方服务 https://webapi.cninfo.com.cn/ ，财联社 https://image.cls.cn/html/privilege/agreement.html ，金十 https://open.jin10.com/ ，新浪 https://finance.sina.cn/app/SFAuser.shtml 。规则访问未知不当作已获许可。

## 6. 产业链研究深度

同一研究区分三层：材料→工艺→部件→系统→终端用途；具名主体的已披露业务；待检验的经济传导推断。送样、认证、小批量、量产、交付、收入确认必须分开。用途不等于客户关系，合作框架不等于收入。

每条链回答需求怎样经过订单、合格产能、交付、收入、利润传导，在哪一跳可能中断；以认证周期、良率、交期、可替代性、扩产约束、价格/成本为证据。图的连接数、概念标签和股价相关性不证明瓶颈。至少完成一个真实主题的资料—Claim—关系—反证—报告完整样本；缺失的中间环节保留断点，不画成已证实全链。

## 7. 能力与任务统一

保留现有受控 MCP 桥和短时 owner/conv/run 令牌；页面与 Agent 调用同一业务服务。每个动作记录实际参数、结果快照、原任务 ID、来源会话、数据时点、开始/终止状态。

能力矩阵覆盖行情/基本面、K 线、指标列表/创建/计算、自选读取/更新、扫描开始/条件/状态/列表/取消、分析开始/状态/列表/保存、Vibe 开始/状态/列表/追问/取消、报告列表/详情/保存、产业查询与研究证据读取。管理用户、配置、任意网络/SQL/文件/命令、生产发布不暴露为研究工具。

取消与状态轮询不能跨用户，不能把“请求取消”写成“已取消”；进程重启恢复已有工作或明确中断。读取超时不重发开始操作。旧会话可读，已完成结果不会因为回看而改变日期、耗时和版本。

## 8. 可视化交付、上线和介入

采用同一发布 ID 串联方案验收、完整提交、候选摘要、检查、备份验证、预检、准备、切换、验收、完成/恢复。Prism 管理页读取脱敏发布记录；独立于应用的 GitHub 发布记录/工作流保留原始阶段和链接，应用不可用仍可查看。未接入的动作不能显示为可操作按钮。

生产执行器位于应用之外，使用 Mac 已认证 SSH，不在公有 runner 保存生产密钥。固定目标、目录、服务、候选和动作，拒绝任意命令/下载地址；有单写锁、阶段 journal、预期当前版本比较和取消边界。用户可通过独立记录中的操作指引停止剩余阶段；“已请求停止/已停止/切换已发生/状态待核对”分开。既有切换不会因取消工作流而自行撤销。

上线流程按顺序执行：

1. 重新只读盘点服务实际工作目录、解释器、依赖、配置/数据/报告/sidecar、任务、空间与源文件摘要；不输出配置值。比较旧备份和现状，保护新增线上成果。
2. 对在线 SQLite 使用一致性备份；保全相关文件和 Vibe。加密传回 Mac Git 工作区之外，核对逐文件摘要、数据库完整性、Git 对象、重新解密和隔离启动。备份失败不得切换。
3. 冻结最终完整提交，隔离测试和独立审查通过。将已审核的候选验证器与待发布代码分开固定版本，不凭可移动分支或候选自行声称验证通过。
4. 在新版本目录和新依赖环境准备；实际依赖来源固定，禁止原地覆盖/原地升级。运行数据、认证配置、上传/报告与源码分离；迁移只允许已演练兼容的增量变更。未经验证的应用不得导入生产数据库。
5. 在独立端口和生产数据脱敏/隔离副本上进行完整启动、登录、权限、真实依赖接口、研究和历史验收；实时集成检查写明调用和结果，不能用 mock 结果冒充线上数据。
6. 再核对取消、锁、预期当前摘要、在线工作和数据库兼容性；采用可逆版本路径切换，保存旧工作目录/解释器/配置映射；随后受控操作现有服务。
7. 核对实际服务 PID/工作目录、完整修订号、ready、登录、权限和核心旅程；真实模型/行情/sidecar分别验收。失败则按兼容性回退程序和环境，保留当前数据库，不默默恢复旧数据。
8. 验收后记录成功及上线后观察结果；旧版本和备份保留，不自动删除。发布期间未知/异常必须保留，不能覆写为绿色。清单外变更标记未归属。
