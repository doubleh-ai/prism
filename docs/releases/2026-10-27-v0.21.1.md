# v0.21.1 个股研究传输配置修复

Astock 使用独立的 TradingAgents 提供方 SDK。研究对话使用的 Anthropic
兼容 Messages 地址不能自动成为 Astock 的 OpenAI 兼容 Chat 地址。此前默认继承
`ANTHROPIC_BASE_URL`，并再次拼接 `/v1`，会让个股分析请求进入错误路径。

现在只有显式的 `ASTOCK_LLM_BASE_URL` 影响该引擎的自定义基地址；原路径完整保留。
不设置时交给实际提供方 SDK 选择默认地址。DeepSeek 配成含 `/anthropic` 的路径时，
分析在构造图和模型调用前以明确错误结束，不自动改地址或切换执行器。

认证沿用 SDK 的启动配置，例如 DeepSeek 的 `DEEPSEEK_API_KEY`。移除了实际上
不会被该图读取的 `ASTOCK_LLM_API_KEY` 设置；服务不会把研究对话的密钥隐式复制给
另一个协议，不会在并发研究线程中更改全局环境。凭证继续存放在 Git 之外。

本版本延续 v0.21.0 的全平台 Native-only 约束。两份源码与各自的实际验收必须分别
固定；版本、单元测试或候选制品本身均不构成生产发布或恢复可用证明。

依赖锁也按 AkShare 的真实平台声明选择 JavaScript 引擎：Linux 使用
`py-mini-racer`，其他平台使用 `mini-racer`。两者提供相同的顶层 Python 包名，
因此不能同时安装并用覆盖后的文件冒充完整依赖。完整运行环境仍须单独验证
传递依赖、外部引擎源码和实际安装文件。
