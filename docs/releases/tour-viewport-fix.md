# 引导卡片越界修复

状态：已在隔离工作区验证，等待受控发布；本记录不代表已经更新生产。

模型选择等位于页面底部的步骤可能只显示卡片标题，正文和下一步按钮落到窗口外。原因是代码在卡片仍为 `display:none` 时测量尺寸，得到零高度，误判下方空间足够。

修复先让卡片参与布局，再测量真实尺寸。下方放不下时移到目标上方，最后按可见视口四边约束位置；结束步骤也采用同样边界。窄窗口限制卡片宽度，矮窗口中的长说明可以内部滚动，操作按钮不随正文滚走。窗口、嵌套滚动、可见视口及元素尺寸变化触发重新定位，关闭时移除监听和未完成的布局回调。相关静态资源版本已更新，避免浏览器继续使用旧缓存。

验证：

- 回归脚本执行实际引导代码，原版本可以复现越界，修复后通过。覆盖底部与右侧边界、窄屏、长内容、结束步骤、可见视口缩放/偏移、滚动及事件清理。
- 原有 18 项前端流程场景通过；引导、流程、登录页缓存一致性、研报与 Vibe 静态契约五项 Python 测试入口通过；JavaScript 语法与新增 Python 静态检查通过。完整 CI 发现共享缓存契约与旧版本断言，已将应用页、登录页、Service Worker 和对应检查统一升级到资源版本 88。
- 真实浏览器验证 1388×668、320×568 和 390×240；卡片及按钮均在可见区域，长说明可以滚动，下一步按钮可点击。缩放视口偏移另由回归脚本模拟，不声称验证了所有真实设备的键盘与缩放行为。

没有后端、数据、认证、模型或服务控制改动。页面验证使用 `tests/tour_fixture.html` 加载实际样式和引导脚本，不需要生产账号。

## 统一对话宽度

根据用户反馈移除顶栏“宽窄切换”按钮及其切换逻辑。对话回答、欢迎页和输入区采用同一最大宽度 880px；可用空间不足时自动收窄，小屏仍使用响应式布局。登录初始化时清理旧的 `cl-wide` 偏好，主题切换不再携带宽屏状态。行情图表等独立工作区保持原有布局。此改动纳入同一尚未发布的资源版本 88，客户端诊断中的资源版本也同步为 88。
