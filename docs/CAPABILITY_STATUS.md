# 功能支持范围与后续工作

下表描述开发中 v0.24.0 的源码支持范围；该版本尚未发布。表格不记录特定实例的部署状态。部署时应分别验证 Native 研究、Work 协作与跨设备、期货外部数据、反馈常驻消费及各模型提供方；源码支持和自动化回归不代表这些用户旅程均已完成线上验收。

产业关系复用已有结论时保留自动节选复核意见、未覆盖范围和人工状态；有疑点的支持材料不自动进入传导链。意见只在既有证据详情展开，自动支持也不代表事实成立，见[研究质量](research-quality.md)。

本版复核协议另外检查引用方向：反证不能独自支撑“支持”标签，未引用已提供的反方节选时
整体支持范围保持未核全。十二项合成质量样例与评分器已纳入开发回归；这不表示真实模型
已经通过这些样例，也不替代完整研究、原始来源或生产验收。

界面新增与清理遵循 [界面规范](ui-guidelines.md)。本版以 DoubleH 为统一入口和账号，Prism 与 Work 平级且分别导航。现有账号继续使用；个人工作内容不自动传给投资研究，不建立默认的产品间数据联动。

Work 首页支持“提出要求—安排预览—确认—结果—撤销”。常规创建，以及任务状态/优先级、项目状态和指定日期改期由站内规则整理；复杂要求只有用户显式选择后才交给已获工作内容权限的直接 HTTP 模型。模型不读取已有记录、不提供写入身份或版本；服务器在本人资料内匹配任务、项目或日程，并展示原值与新值。同名或日期不清先澄清。整组提交与撤销各自原子完成，并发修改会拒绝覆盖；未知结果按原编号核对。重复日程可单次调整时间与取消，提醒和导出使用实际时间。项目协作、依赖排程、附件、指定成员审批和相关站内提醒已包含在本版源码，仍需独立业务验收。详见 [Work 使用指南](work.md)。

## 怎样使用

1. 从 DoubleH 首页进入 Work，首次点击“启用我的工作台”。任务设置截止时间后也会出现在日历列表。
2. 打开“日历安排”，设置开始和结束时间。重叠会提示但不禁止保存；其他设备修改过的版本会拒绝覆盖。取消保留记录，ICS 导出可交给其他日历应用导入。
3. 打开“研究偏好”主动保存约束。之后创建的 Native 研究保存该版本，正在执行及历史研究不会被新设置改写。
4. Prism 内的“期货研究”选择品种后，点击“开始研究”创建 Native 研究对话并提交固定范围的问题；沿用现有停止、保存与回放。“查看资料”不调用模型，分开显示已取得的价格、技术计算、交易所资料和待补证问题；一路来源失败时保留其他资料。不同日期不能当作同日比较。新入口属于未发布候选，真实模型与生产流程另行验收。

这些是可验证的基础能力，不把未采集的基本面数据包装成已经完成的深入研究。持仓量变化不等于资金净流入，连续序列不等于可交易合约，未掌握实际组合时风险状态保持未评估。

## 交付与后续边界

| 优先级 | 工作 | 完成标准 |
|---|---|---|
| P0 | 每个实例的受控部署与业务验收 | 绑定固定版本，验证停止、任务保护、备份恢复、实际公网版本，以及该实例使用的研究、Work、数据与反馈流程 |
| P1 | 业务监测与私有反馈处理 | 专用受限身份读取新队列，按功能运行无真实用户数据的合成流程；失败与未知可见 |
| 所有者后置 | 邮箱找回与外发渠道 | 等待发信服务；启用时单独完成域名、绑定、限流、验证码、会话撤销和真实投递验收 |
| P1 | 期货证据覆盖 | 按品种接官方库存、现货/期限及会员数据，保留口径、日期、来源和缺口，禁止混用连续合约与具体合约 |
| P2 | Work 后续能力 | 任务、日程、项目协作、依赖排程、附件及审批本版源码提供；当前范围须完成最终集成与生产验收，外部渠道继续后置 |
| P2 | 可审查的知识积累 | 引用溯源、有效期、冲突与复核；历史模型回答只能是观点，不能通过重复引用变成事实 |
| P2 | 云端修复与用途路由 | 先复现和验证再提私有修复候选；遵守 Mac 优先和统一生产写锁，不直接热改生产 |

新增费用、外部账户或隐私范围变化单独决定；普通开发和隔离验证继续推进。已发布基线见 [v0.23.0 版本说明](releases/v0.23.0.md)，部署要求见[发布规范](release-process.md)。
