界面新增与清理遵循 [界面规范](ui-guidelines.md)。本候选以 DoubleH 为统一入口和账号，Prism 与 Work 平级且分别导航。现有账号继续使用；个人工作内容不自动传给投资研究，不建立默认的产品间数据联动。

Work 首页支持“提出要求—安排预览—确认—结果—撤销”。常规创建，以及任务状态/优先级、项目状态和指定日期改期由站内规则整理；复杂要求只有用户显式选择后才交给已获工作内容权限的直接 HTTP 模型。模型不读取已有记录、不提供写入身份或版本；服务器在本人资料内匹配任务、项目或日程，并展示原值与新值。同名或日期不清先澄清。整组提交与撤销各自原子完成，并发修改会拒绝覆盖；未知结果按原编号核对。重复日程可单次调整时间与取消，提醒和导出使用实际时间。项目协作与依赖排程已进入候选；附件、审批和跨项目资源协调仍待实现。详见 [Work 使用指南](work.md)。

## 怎样使用

1. 从 DoubleH 首页进入 Work，首次点击“启用我的工作台”。任务设置截止时间后也会出现在日历列表。
2. 打开“日历安排”，设置开始和结束时间。重叠会提示但不禁止保存；其他设备修改过的版本会拒绝覆盖。取消保留记录，ICS 导出可交给其他日历应用导入。
3. 打开“研究偏好”主动保存约束。之后创建的 Native 研究保存该版本，正在执行及历史研究不会被新设置改写。
4. 打开“期货研究”，选择品种并获取日线。页面分开显示技术计算、成交持仓和待补证的基本面问题。继续研究先创建会话并预填问题，点击发送才调用模型。

这些是可验证的基础能力，不把未采集的基本面数据包装成已经完成的深入研究。持仓量变化不等于资金净流入，连续序列不等于可交易合约，未掌握实际组合时风险状态保持未评估。

## 下一批建议顺序与验收条件

| 优先级 | 工作 | 完成标准 |
|---|---|---|
| P0 | 本候选受控验收与发布 | 固定提交、兼容恢复候选、加密备份实际恢复、独立停止、任务保护、生产用户流程和精确版本全部核对 |
| P1 | 业务监测与私有反馈处理 | 专用受限身份读取新队列，按功能运行无真实用户数据的合成流程；失败与未知可见 |
| P1 | 邮箱找回 | 域名与发信配置、绑定验证、限流、验证码失效、会话撤销及实际投递验收 |
| P1 | 期货证据覆盖 | 按品种接官方库存、现货/期限及会员数据，保留口径、日期、来源和缺口，禁止混用连续合约与具体合约 |
| P2 | Work 后续能力 | 个人项目、重复日程、项目协作与依赖排程已进入候选；附件、审批、跨项目资源及跨渠道送达待完成 |
| P2 | 可审查的知识积累 | 引用溯源、有效期、冲突与复核；历史模型回答只能是观点，不能通过重复引用变成事实 |
| P2 | 云端修复与用途路由 | 先复现和验证再提私有修复候选；遵守 Mac 优先和统一生产写锁，不直接热改生产 |

新增费用、外部账户或隐私范围变化单独决定；普通开发和隔离验证继续推进。详细边界见 [候选验收清单](releases/native-v0.22.0-candidate.md)。
