# Prism 项目指南

本文面向重新接手项目的使用者和开发者。先掌握页面与记录的关系，再按需要阅读代码；无需先读完历史方案。

本指南描述仓库中的 Native Agent 源码与使用方式，不记录特定实例的部署状态。版本与部署的区别见 [README](../README.md#版本与上线状态)。

## 5 分钟概览

Prism 目前是一个带账号隔离的研究工作台，不是自动交易系统。核心路径是：

1. **提出问题**：在“研究对话”选择综合研究、产业链研究或公司研究。写清楚对象、时间范围和希望解决的问题。
2. **查看过程**：回答中会出现实际发生的工具调用、研究时点、来源和缺口。打开调用卡片查看原结果，不会重新运行一次任务。
3. **核对证据**：交易所和公司披露适合确认事实；新闻可以提供线索；平台行情和历史观点都有自己的时效与局限。
4. **回到工作区**：行情、指标、产业关系和网页研报保留专用页面。对话与页面通过已有记录关联，而不是各存一份无法追溯的结果。
5. **继续研究**：可以回看报告、追问或要求比较新旧证据。保存记录并不代表模型会自动学习，也不代表结论已被确认。

适合这样提问：

> 请研究这家公司最近一期财报的经营变化。优先使用交易所或公司公告，注明报告期间和发布时间；把已披露事实、计算和判断分开，缺资料的地方直接列出来。

> 请分析液冷产业链的关键环节。区分产品用途、客户认证和已披露供货关系，说明订单如何传导到收入与利润，并列出每一跳的证据及失效条件。

普通问题可以简答，不需要每次生成长篇报告。若要求“截至某日”，应核对来源在该时点是否已经公开，而不只看今天的服务器日期。

## 功能与当前限制

“页面已有”与“原生 Agent 可以调用”是两件事。原生目录以登录后 `GET /api/agent/tools` 返回值为准；没有提供的能力不会隐式换用旧引擎。

| 页面或能力 | 当前可用范围 | 需要知道的限制 |
|---|---|---|
| 研究对话 | Native 候选直接调用配置的模型 API，支持工具循环、历史上下文、保存与停止 | 需要有效模型配置；每轮有时间、请求和工具预算；完成不等于结论核验通过 |
| 行情工作区 | 行情、基本面、K 线、标的搜索；原生 Agent 可查询 | 供应商、网络和缓存会影响时效；查看结果中的数据时间和回退提示，不保证所有市场实时覆盖 |
| 指标实验室 | 查看和计算已有指标；原生 Agent 可列举、执行 | 原生工具暂不提供自然语言转指标代码、任意代码执行或随意修改指标 |
| 自选与扫描 | 账号自选及原有扫描页面；原生 Agent 可读自选、查询已有扫描状态 | 原生 Agent 暂不发起扫描或修改自选；新增任务仍须走已有页面的明确操作 |
| 产业关系 | 查询图谱、上下游与关联研究；原生研究可登记本轮主张和关系候选 | 种子图及连接数不证明商业关系；登记候选不会自动把它升级为已验证的全局知识 |
| 网页研报 | 已保存报告、研究版本、证据与原会话回看 | 历史报告可能缺少可靠研究时点或原始材料；生成或保存时间不等于数据截至时间 |
| 个股分析 | Astock 工作区使用可选第三方 Python 引擎 | 原生 Agent 只读取已有任务状态，不启动；并非自有 Agent 或 CLI 回退 |
| 深度研究 / Vibe | 可查看本账号已保存历史 | 新研究与追问明确返回 503，等待独立隔离验收；不是当前可用执行能力 |
| 历史知识检索 | 搜索、读取当前账号的研究和报告，排除本轮自引用 | 当前是有界文本检索，不是全量向量库、自动事实审查或模型训练 |
| 管理与发布 | 管理员可观察脱敏发布与检查记录 | 研究 Agent 没有部署、重启、管理员或任意 Shell 权限；管理页不是生产执行器 |
| 反馈与建议 | 支持自己的反馈、规则分诊、管理员评审与处理历史 | 状态台账不会自行热修；可选定期处理需由部署所有者单独配置与验证，修复走受控发布 |

反馈填写、状态含义、隐私边界与建议每日评审见 [反馈说明](FEEDBACK.md)。

### 来源与时间怎样看

当前来源读取器默认允许交易所、巨潮以及财联社、金十、新浪财经的指定域名，具体名单在 [`server/agent/sources.py`](../server/agent/sources.py)。公司官网需由维护者明确加入 `PRISM_RESEARCH_SOURCE_HOSTS`，模型不能自行扩大名单。

这表示工具**允许尝试读取合适的公开页面**，不表示已经接入这些机构的全量付费数据或保证每个网页可访问。当前读取的是受限的 HTML / 文本节选，PDF、登录页、反爬限制或无法解析的资料可能失败；保留缺口，不编造原文。服务器网页搜索是否可用也取决于当前提供方的协议与配置。

| 时间 | 含义 |
|---|---|
| 本轮研究截至 / `as_of` | 本轮观察问题的服务器时间，使用 `Asia/Shanghai` |
| 来源发布时间 | 材料何时公开；只有日期时保留日期精度，未知就标未知 |
| 采集时间 | 工具实际取得、接收资料的时间 |
| 数据所属时间 | 行情交易日、财务期间或统计区间，需要按来源单独说明 |
| 保存时间 | 平台保存记录的时间，不能代替上述任一时间 |

搜索结果链接只是线索。拿到页面节选、引用定位匹配、数值口径检查和语义核验是不同步骤；界面标记“待核验”并非显示故障。

### 刷新、停止与失败

Native 候选把后台研究与网页读者分开。刷新或切换会话不会重新发起模型请求；重开活跃会话会读取同一 `run_id` 的有序事件，按序号恢复进度。对话只允许一轮活跃研究，避免重复付费调用。

点击停止首先登记取消意图。页面确认后台进入真实终态后，才结束读者并重新读取最终记录；未能确认时保留已有进度和停止入口。网络中断、预算耗尽、失败和取消分别记录，不能把其中任何一种自动显示成“研究成功”。服务重启也不会自动重放原模型请求。

## 数据保存、知识复用与隐私

默认运行目录由 `STOCK_DATA_DIR` 指定。主数据库为该目录下的 `chat.db`；行情缓存、旧引擎产物等还有各自文件，不能只备份一张会话表。

- **会话**保存用户提问与公开回答；账号和会话归属决定读取权限。
- **原生任务与事件**保存执行状态、事件序号、取消意图和有限用量信息，支持回放，不保存模型私有思考签名。
- **研究账本**保存取得的资料信息、节选、主张、关系候选、版本和未解决缺口。它不保证保存了整份外部网页原件。
- **报告库**保存可在网页阅读的研究快照，与原研究版本关联。原生问答不要求写一个 PDF 文件。
- **历史检索**读取当前账号最近最多 200 份报告和 200 条研究版本记录，以文本匹配生成候选；它不是所有旧记录的完整搜索索引。
- **旧对话迁入**保存于 SQLite 的 `legacy_conversation_history`，服务时不读取旧 CLI 的历史目录。未导入会话显示 `history_migration.status=pending_import`，继续展示已有平台消息。管理员须用 `scripts/import_legacy_history.py` 对预先准备的离线数据库与历史目录副本显式导入；源指纹相同则复用，冲突则整次拒绝。导入不改写现有 SQL 消息或 Native 历史锚点，私有思考和工具块不进入公开历史。

保存的观点仍是带日期、来源和未核验状态的历史材料。复用时需要重新检查时效与原始证据；用户点赞、同一说法重复出现或模型再次引用，都不会自动将其认证成事实。

**平台没有自动训练或微调基础模型的流程。** 但在你发起研究时，为回答问题而选择的当前问题、公开回答上下文、工具结果或检索到的历史节选，会发送给配置的模型提供方。保存在本机不等于永远不会离开本机；服务端应选择合适的提供方及数据政策。

真实 `.env`、API Key、私钥、会话令牌、数据库及 WAL/SHM、用户报告、日志、备份和旧私有 Git 历史均不能进入公开仓库、候选包或公开 CI 产物。环境专属运维源码也放在私有仓库；凭证和运行数据即使在私有 Git 中也不入库。

## 本地开发

以下是新建开发环境的步骤，不是生产安装或升级流程。使用 Python 3.12；完整浏览器脚本回归需安装 Node.js。

```bash
git clone https://github.com/doubleh-ai/prism.git
cd prism
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

mkdir -p "$HOME/.local/share/prism-dev"
export STOCK_DATA_DIR="$HOME/.local/share/prism-dev"
export STOCK_LOG_FILE="$STOCK_DATA_DIR/app.log"
export ADMIN_USER=local-admin
```

首次启动需要给本地管理员设置密码。在同一终端输入以下命令，然后输入你自行选择的开发密码；输入不会回显，也不应把值写进命令历史：

```bash
read -r -s ADMIN_PASS
export ADMIN_PASS
python -m uvicorn server.main:app --host 127.0.0.1 --port 8088 --workers 1
```

打开 `http://127.0.0.1:8088`，用 `local-admin` 和刚输入的密码登录。初始化只创建不存在的账号，不会覆盖已有密码。保持单进程运行；开发自动重载会中断当前任务，不用于检验发布或长期后台研究。

没有模型 Key 时仍能启动并查看页面。需要真实研究时，可在启动前通过本地密钥管理或隐藏输入导出 `DEEPSEEK_API_KEY` 或 `MINIMAX_API_KEY`，并按需设置 `PRISM_DEFAULT_MODEL`。支持的端点与模型配置以 [`server/config.py`](../server/config.py) 和 [`provider.py`](../server/agent/provider.py) 为准；配置存在不保证提供方实际接受调用。

`.env.example` 是变量模板，应用通过 `os.environ` 取值，**不会自动加载 `.env`**。不要复制生产配置和数据库来开发。实时行情的可选依赖见 `requirements-extra.txt`；Astock 需要单独的第三方 Python 依赖。整个 Prism 不安装、不调用或回退到 Claude Code CLI，也不读取外部 Skill。`install.sh` 只准备本地 Python 环境，不启动服务或执行生产部署。

DeepSeek / MiniMax 继续通过直接 HTTP 使用；Anthropic 兼容 Messages 是协议格式，不是 Claude Code 运行时。术语解释、标题、指标翻译等辅助模型同样使用 `server/services/auxiliary_model.py`，失败明确返回错误，不换执行后端。健康页只检查本地 Native 模块、工具目录和模型配置，不能证明真实模型调用成功。

### 验证修改

优先用临时数据、合成账号和模拟提供方验证行为。真实外部接口单独做有限验收，记录目的地、请求和用量边界。

```bash
python -m pytest -q tests/test_native_agent_api.py tests/test_native_agent_frontend.py tests/test_native_agent_http_journey.py
python -m pytest tests/ --cov=server --cov-report=term-missing
python -m ruff check server/ tests/
python -m ruff format --check server/ tests/
```

Ruff 需另装开发依赖。部分集成测试会启动本机临时 TCP / Unix socket，受限执行环境需要允许本机通信；这不应改成访问生产。测试夹具应使用独立 HOME / 数据目录并清除继承凭证。导入应用会初始化数据库，因此在导入前就要指定开发路径。

`Makefile` 提供常用别名，但其中 lint / format 目标会吞掉非零退出码；需要判断是否通过时使用上面直接命令及 CI 的实际结果。不要把开发启动、CI 绿色或 `/health/ready` 返回 200 当作真实上线完成。

### 增加一种平台能力

先判断它是纯读取、会修改数据，还是会启动后台任务。随后按[架构文档的扩展步骤](ARCHITECTURE.md#增加能力的最小路径)完成 schema、账号授权、真实任务归属、结果快照和错误合同，再纳入原生白名单。不要只把旧启动函数改个工具名字。

新增模型提供方要实现现有有限流协议，先测试分帧、工具参数、停止原因、用量缺失和中断，再用有限真实请求验收。增加更多 Agent 框架或外部 Skill 不是必需步骤。

## 如何读代码

从一个具体问题出发，比从文件清单逐个读更快：

| 想理解或修改的问题 | 建议顺序 |
|---|---|
| 一个问题如何开始、去重、保存 | `agent/api.py` → `agent/store.py` → `agent/runtime.py` |
| 模型流如何变成网页内容 | `agent/provider.py` → `api.event_payload` → `app.chat.js` |
| 刷新和停止为什么不会重跑 | `app.core.js` / `app.chat.js` → `agent/api.py` → `store.py` |
| 工具怎样限制账号和权限 | `agent/tools.py` → `capabilities.py` → `work_lifecycle.py` |
| 来源、日期和引用如何记录 | `agent/sources.py` → `research_context.py` → `research/ledger.py` |
| 历史知识怎么找 | `agent/knowledge.py` → `agent/public_text.py` |
| 网页报告与产业关系怎么显示 | `app.reports.js` / `app.research.js` / `app.industry.js` |
| 某项约定是否真实实现 | 找同名 `tests/test_native_agent_*.py` 及相应页面回归 |

上表的 Python 文件在 `server/`，JavaScript 在 `static/js/`。完整调用图和数据库职责见 [ARCHITECTURE.md](ARCHITECTURE.md)。`docs/superpowers/`、旧 release notes 和早期演进方案保留历史上下文；其中计划、路径和状态不能代替当前代码与发布回执。

## 发布、停止与回退

日常开发结果先进入独立分支和可审查 PR。`master` 是代码主线；把最新代码同步到它，不等于服务器已经切换。

1. **看进度**：部署所有者应维护独立于应用的受限记录，标识固定提交、产物、阶段与实际结果。不要把实例回执或运行数据复制到公开 issue。
2. **紧急介入**：部署所有者应提供独立停止入口，并在每个受控边界前重新核对。停止状态未知或不可读取时不得继续。停止不能自动撤销已完成的切换，也不等于后台任务已经全部结束。
3. **正常上线**：冻结完整提交和产物 → 隔离验收 → 新加密备份与实际恢复 → 维护入口和任务排空 → 切换 → 内部用户旅程验收 → 恢复入口 → 外部核验。具体环境命令由部署所有者受限维护。
4. **遇到异常**：先停止后续阶段，保留失败记录并核对实际现场。只能回退到与当前数据库兼容、已验收的代码和环境。程序回退不会自动还原数据库；丢弃新写入的恢复必须另行明确授权。

部署与恢复必须使用经过独立验证的 Native-only 流程，不能为满足旧门槛重新引入 CLI。应用管理员的发布页是观察入口，不能执行服务器命令。GitHub Actions 的取消按钮只取消该工作流；`install.sh`、临时部署脚本或递归复制源码都不能替代受控升级。详见 [发布规范](release-process.md) 和 [任务归属说明](work-lifecycle.md)。
