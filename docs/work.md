# Work：任务、项目与日程

Work 是 DoubleH 下独立的工作平台，与 Prism 共用账号；工作内容不会自动进入投资研究。
下述功能属于开发候选，是否可用以实例实际部署版本为准。

任务、项目和日历共用 Work 导航。各页面右上角的“提醒”打开当前页面内的侧栏，
查看到期、项目与审批通知，标为已读后可直接回到原操作；不会跳转到另一个平台。
旧 `/notifications` 链接仍有效，会在 Work 内打开提醒。

“反馈与建议”也在当前 Work 页面打开，提交后可直接查看同一条反馈的答复和处理进度。
关闭后回到原任务、项目或日程，未保存输入会保留；无需跳到 Prism。

## 从一句要求开始

打开 Work，在原有安排输入框说明目标，例如：

- `创建任务 整理评审材料`
- `每周一上午10点提醒我开项目会，1小时`
- `把任务「整理评审材料」标为已完成`
- `把任务「整理评审材料」设为高优先级`
- `把明天的周会改到下午3点`
- `把项目「发布」标为归档`
- `在项目「发布」中添加任务「准备材料」`
- `把项目「发布」的任务「准备材料」负责人设为xiaoli`
- `把项目「发布」的任务「准备材料」工时设为120分钟`
- `在项目「发布」中让任务「准备材料」完成后开始任务「评审」`
- `查看项目「发布」的进度`
- `在项目「发布」中发起审批「材料评审」交给「xiaoli」`

系统先展示安排预览。修改已有内容时，会列出原值与新值；日程会明确区分“只调整
这一次”和“整组重复日程”。核对后确认即可；结果可以回到原任务、项目或日历查看。
不需要知道记录编号或版本，也不需要重新填写已有内容。

常规要求由本地规则整理。规则无法理解时，可以修改要求，或主动选择模型整理。
模型只收到这条要求、当前时间和公开字段说明；它不会收到已有工作记录、投资研究
或其他账号资料。模型还需由管理员启用工作内容用途，不能自行写入或调用其他工具。

已有对象由服务器在本人资料或明确接受邀请的项目内匹配。同名任务需区分名称；同名日程需补充日期。
没有找到时不会猜一个对象代替。日期、夏令时有歧义时先澄清。当前内容已经符合要求
时无需重复修改；这类澄清不会继续推荐无用的模型调用。

## 确认、撤销与多端

一次提案中的改动和完成回执在同一个事务中保存；其中任一步失败，整组改动都不提交。
另一台设备已经修改过内容时，原预览会拒绝覆盖，需要重新整理。预览有效期15分钟。

撤销也以整组为单位，按相反顺序恢复更新前的内容，或取消/归档刚创建的对象。后续
已有修改时会拒绝撤销，保留现状。操作结果未知时，先使用原提案核对，不重新发送
同一个模型请求或创建另一批记录。

数据保存在服务端，同账号可以在其他设备读取。未保存输入不跨设备同步；暂不支持
离线编辑。浏览器刷新不能替代核对尚未确定的操作结果。

## 日程与提醒

支持单次及每日、每周、每月重复日程。重复有明确结束条件，最多366次、十年范围。
不存在的月份日期或夏令时跳跃会跳过；重复本地时间需要明确偏移，不静默猜测。

调整某一天时，其他日期不受影响，提醒使用该次的新时间。整组编辑会保留已有单次
改期和取消；如果新规则会删除这些例外，保存会拒绝，需先处理例外或明确请求重置。
日程重叠会提示，系统不会擅自删除或移动另一个安排。

ICS 导出包含有限的 UTC 日期集合。单次改期保留原系列 UID，并按
[iCalendar 的单次例外规则](https://datatracker.ietf.org/doc/html/rfc5545#section-3.8.4.4)
记录原定时间与实际起止时间。文件导出不等于与第三方日历双向同步；具体客户端仍需
独立验证。站内提醒已接通，邮件、短信和设备推送尚未启用。

## 项目协作与时间安排

项目负责人可以向已有账号发送站内邀请，选择查看或编辑权限。对方接受后才可访问
项目说明、关联任务、排程、附件、审批和项目操作记录；不会共享负责人的其他任务、日历或研究。
编辑成员可以处理项目任务和排程，查看成员只读。成员可退出，负责人可撤销邀请
或调整成员权限；服务端即时重新检查权限，旧预览不能绕过权限变化。

“时间安排”按项目工作时段、时区、工作日及额外休息日计算剩余工作。可以设置工时、
负责人、不早于时间、零工时里程碑以及完成后开始的依赖。同一项目内同一负责人
的任务不会重叠；不同项目的资源占用暂不合并。前置任务未完成时，后续任务不能
标为进行中或完成；后续已经开始，也不能直接重新打开已完成的前置任务。

排程是估算，不是实际进度或交付保证。缺少工时时暂按60分钟，并明确标记；未分配
的任务按可并行计算，需要继续安排。假期由项目自行设置，不代表内置法定假日。
取消的前置任务、不可用负责人、依赖循环及范围外时间不会被悄悄忽略。浮动时间和
关键任务反映当前估算、依赖、截止日期及本项目人员顺序；不宣称已经求出全局最优。

状态、工时、负责人和依赖可以通过同一个 Work 助手处理；复杂工作日历可在项目
页面设置，或显式选择模型整理本条要求。相关变更集中预览、原子确认与撤销；
并发改动或成员权限变化后，需要重新核对，而不是覆盖其他人的安排。

## 附件与审批

附件与审批放在项目原有详情中，默认收起。附件按项目权限共享，上传前会说明范围；
支持UTF-8文本、Markdown、CSV、PDF、PNG和JPEG，每份最多5MiB，每项目最多30份，
同一负责人所有项目合计100MiB。可选关联项目任务。文件保存在服务端业务数据库，
随数据库备份；按原始字节保存并记录SHA-256。下载每次检查当前权限，强制作为文件
下载，不在站内执行或预览，不自动解析或交给模型；格式校验不等于杀毒扫描。
上传者或项目负责人可以移除附件；被撤销权限后不能继续下载，移除不能通过重发
上传请求复活。文件已被用户下载到其他设备后，系统无法收回本地副本。

编辑成员可以选择另一位已接受邀请的编辑成员或负责人发起审批。申请保存说明、
指定审批人、所选任务版本及附件指纹；不会偷偷纳入未选择的材料。指定审批人手动
通过或拒绝，拒绝需填写理由；申请人或负责人可以撤回待处理申请。任务、附件或
人员权限变化后旧申请不能直接通过，需撤回并重新发起。已决定的记录不能用助手
撤销覆盖。审批记录决定本身，不自动触发付款、发布或任务状态修改。

助手支持查询项目摘要和发起待审批申请。只读查询不要求再次确认，也没有撤销按钮；
申请先预览后确认，未处理时可撤回。复杂申请可显式选择模型整理，但模型只收到
本条要求，任务及附件名称在服务器本地匹配，不读取文件正文，不代替审批人判断。
待审批、审批结果和已分配项目任务的截止提醒复用原站内提醒入口，不新增一套收件箱。

## 当前边界

支持本人任务、项目和日程的创建与更新，重复日程的单次调整、站内提醒、预览确认和
撤销。单次例外目前只修改时间和取消状态；修改重复日程名称等内容需明确选择整组。
同一对象在一份提案中有多次修改时，需合并成一个明确要求。

团队成员权限、里程碑、依赖排程、附件及审批已进入候选源码，仍需相应上线验收。
跨项目资源协调、外部双向同步和外部消息送达不在当前基础协作范围内。完整范围见[功能支持表](CAPABILITY_STATUS.md)，
接口合同见 [API](API.md#v0230-completion-work-unreleased)。
