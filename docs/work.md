# Work：任务、项目与日程

Work 是 DoubleH 下独立的工作平台，与 Prism 共用账号；工作内容不会自动进入投资研究。
下述功能属于开发候选，是否可用以实例实际部署版本为准。

## 从一句要求开始

打开 Work，在原有安排输入框说明目标，例如：

- `创建任务 整理评审材料`
- `每周一上午10点提醒我开项目会，1小时`
- `把任务「整理评审材料」标为已完成`
- `把任务「整理评审材料」设为高优先级`
- `把明天的周会改到下午3点`
- `把项目「发布」标为归档`

系统先展示安排预览。修改已有内容时，会列出原值与新值；日程会明确区分“只调整
这一次”和“整组重复日程”。核对后确认即可；结果可以回到原任务、项目或日历查看。
不需要知道记录编号或版本，也不需要重新填写已有内容。

常规要求由本地规则整理。规则无法理解时，可以修改要求，或主动选择模型整理。
模型只收到这条要求、当前时间和公开字段说明；它不会收到已有工作记录、投资研究
或其他账号资料。模型还需由管理员启用工作内容用途，不能自行写入或调用其他工具。

已有对象由服务器在本人资料内匹配。同名任务需区分名称；同名日程需补充日期。
没有找到时不会猜一个对象代替。日期、夏令时有歧义时先澄清。当前内容已经符合要求
时无需重复修改；这类澄清不会继续推荐无用的模型调用。

## 确认、撤销与多端

一次提案中的改动和完成回执在同一个事务中保存；其中任一步失败，整组改动都不提交。
另一台设备已经修改过内容时，原预览会拒绝覆盖，需要重新整理。预览有效期15分钟。

撤销也以整组为单位，按相反顺序恢复更新前的内容，或取消/归档刚创建的对象。后续
已有修改时会拒绝撤销，保留现状。操作结果未知时，先使用原提案核对，不重新发送
同一个模型请求或创建另一批记录。

数据保存在服务端，同账号可以在其他设备读取。未保存输入不跨设备同步；暂不支持
离线编辑。浏览器刷新不能替代核对尚未确定的操作结果。

## 日程与提醒

支持单次及每日、每周、每月重复日程。重复有明确结束条件，最多366次、十年范围。
不存在的月份日期或夏令时跳跃会跳过；重复本地时间需要明确偏移，不静默猜测。

调整某一天时，其他日期不受影响，提醒使用该次的新时间。整组编辑会保留已有单次
改期和取消；如果新规则会删除这些例外，保存会拒绝，需先处理例外或明确请求重置。
日程重叠会提示，系统不会擅自删除或移动另一个安排。

ICS 导出包含有限的 UTC 日期集合。单次改期保留原系列 UID，并按
[iCalendar 的单次例外规则](https://datatracker.ietf.org/doc/html/rfc5545#section-3.8.4.4)
记录原定时间与实际起止时间。文件导出不等于与第三方日历双向同步；具体客户端仍需
独立验证。站内提醒已接通，邮件、短信和设备推送尚未启用。

## 当前边界

支持本人任务、项目和日程的创建与更新，重复日程的单次调整、站内提醒、预览确认和
撤销。单次例外目前只修改时间和取消状态；修改重复日程名称等内容需明确选择整组。
同一对象在一份提案中有多次修改时，需合并成一个明确要求。

团队成员权限、里程碑和任务依赖排程、附件、审批及外部双向同步仍待实现；不会把
个人项目包装成已经完成的团队项目管理。完整范围见[功能支持表](CAPABILITY_STATUS.md)，
接口合同见 [API](API.md#v0230-completion-work-unreleased)。
