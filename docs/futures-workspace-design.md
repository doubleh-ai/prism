# Prism 期货研究工作区设计

2026-11-24 · 评审稿 · 代码基线 `a6fe7812`

用户打开一个品种，应当能回答三个问题：最近发生了什么，哪些证据支持或削弱了我的判断，能否用当时可见的数据复核。期货留在 Prism 的研究导航内，沿用 DoubleH 账号、Native 对话、研究保存与回放。

## 先修正研究对象

现有实现值得保留三处：按来源读取行情和交易所资料，保留每个观测的日期与单位，以及把工具结果登记为可回读的研究证据。首轮工作集中在选品种、读资料、发起研究这条用户路径。

| 在当前代码和离线用例中核实的现象 | 用户影响 | 处理 |
|---|---|---|
| 后端目录有 33 个品种；模板、深链接和研究交接分别维护 16 项名单 | 铁矿石等品种能出现在数据表里，选择研究时却找不到 | 由服务端目录生成一个可搜索的选择器，旧链接兼容 |
| 在合成页面上从 RB 点击黄金，详情请求为 AU，供“开始研究”读取的值仍是 RB | 研究可能跑错品种，且请求能够正常完成 | 用一个选中状态驱动标题、URL、详情和发送；切换后丢弃旧请求的迟到响应 |
| 面板显示行情、跨期、仓单、基差；现货历史已注册为 Native 工具；“开始研究”仍拼接固定的全面研究提示 | 看见价格变化后，想追问其中一段，只能重新说明上下文 | 复用现有对话交接，传入用户的问题、品种、合约、时间区间和正在看的证据 |
| 面板的日期参数仅传给跨期；另外三个维度各取最新 | 回看历史某日可能混入之后的信息 | 最新视图逐项标观测日；历史视图约束每项的可见时间，未提供历史读法的维度显示缺口 |
| 代码目录登记行情 33、仓单 24、基差 24、跨期 4；现货历史映射 24 | 静态“可用”容易被理解为今天已取到数据 | 目录只表达来源支持范围，详情以实际取得的日期和状态为准 |

覆盖数字来自本地代码。现有面板 4 个场景、Native 入口 7 个场景均通过；两组测试分别验证了展示与发送，缺少从目录点选后再发起研究的串联场景。

## 用户怎么用

首屏只放品种选择、行情图和当前问题。选择螺纹钢后，主图默认显示连续日线并标明口径；下方依次列出有数据的基差、跨期与仓单观察。每条显示数值、单位、观测日期，可展开查看具体合约、公式和来源。保留一个“问 Prism”输入区；读图、切品种或展开来源均不调用模型。窄屏把观察排成单列，来源在原位置展开。

例如用户问“这次螺纹钢走强，现货也跟了吗？”先对齐两个观察日的现货、当日对应主力合约与期价，拆出基差变化来自哪一边。若主力已切换，标出两份合约并分别解释。再看同日各交割月结算价与仓单，说明它们支持哪种解释、哪些事实仍未知。点答案中的数字应能回到当次保存的原始行。若只有一天现期对照，仍可回答当天升贴水，历史变化留空。

只显示与品种有关的观察。豆粕可看现货、已披露仓单和大豆年度压榨背景，压榨投入与豆粕产量分别标注。股指在缺少期限对应的指数基差时显示已取得的合约行情，省去商品仓单区块。覆盖目录可在选择品种时按需展开。

## 优先深化的研究能力

| 研究问题 | 平台负责的计算与证据 | 第一批边界 |
|---|---|---|
| 现货和期货谁在动？ | 同日、同单位的现货减主力期价；展示两端数值、主力代码，历史图标注换月 | RB 首发。现货历史单独可画；历史基差须补齐逐日对应合约与期价 |
| 哪个月份最强？ | 绘制同日各挂牌月份结算曲线，点两个合约看“远月减近月”；并列成交量与持仓量，便于发现远月成交稀少 | 先展示已有曲线。现有最远月减最近月保留明确标签；跨日变化只比较同一对合约 |
| 仓单变化值得追查吗？ | 按来源披露单位展示绝对变化、前次披露日期和历史分布。增减异常作为可点开的研究线索 | 比较同口径、同仓单范围；来源缺报、单位变更、历史不足时保留原数，停止异常判断 |
| 波动来自市场还是换月？ | 优先用同一具体合约计算波动；提示当期值、比较窗口和样本数，换月前后分段 | 用历史样本校准后再上线提示。首版只在工作区展示有证据的事件 |
| 我这笔仓位能承受什么价格？ | 经用户主动选择，复用组合已有权益、乘数、方向和保证金情景；由用户的损失预算推算对应价格，并列假设 | 缺少合约、手数或成本约束时说明所缺输入。个人持仓留在账户范围，默认品种研究只读公开资料 |

首批试点选螺纹钢，覆盖行情、基差、跨期和仓单。豆粕作为“部分覆盖”的验收样本，沪深 300 股指作为“商品维度不适用”的样本。用三个品种验同一套工作区，可在增加品种前发现错误的通用假设。

## 如何落在现有代码上

1. 沿用 `futures.catalog()` 和 `/api/futures/panel/catalog`。让模板、旧链接和 Native 交接从同一目录取符号及名称。仍由 `futures_panel.py` 负责展示所需的聚合，保留各来源模块和现有工具契约。
2. 给需要跨日比较的观测补足品种、具体合约或连续序列、价格口径、单位、交易日、来源和可定位的证据。历史回放另记当时可知的发布时间或采集时间。无法还原当时可见性的历史资料只用于事后描述。节假日按实际披露和交易日历核对。上期所样本可从[日周数据与交易日历入口](https://www.shfe.com.cn/reports/tradedata/dailyandweeklydata/)抽查。
3. 拆开读图与长区间读取。首屏优先读取所选品种的短区间，现货历史按需加载；同品种同来源同日期的并发请求可合并。修正历史证据仅以末日区分区间的限制，让不同起点、单位口径和修订版本可独立回放。模型默认收到比较结果、样本量、缺口和证据引用，原始长表按需取页。
4. 事实计算放在 Python，Native Agent 负责理解问题、选择已有工具、组织解释和指出反例。页面和工具复用同一计算。保存时固定证据版本；重开旧对话直接回放，新行情由用户另行刷新。
5. 历史验证分两步。先检验事件发生后第 1、5、20 个交易日的价格变化，披露样本数、重叠事件、基准及分段结果。触发阈值只用观察日之前的数据。再评估策略收益，前提是具备逐日可交易合约、换月、成交时间、手续费和滑点假设。现货工具的 250 个样本及 365 天跨度只作为该现货序列的样本门槛。

## 交付和验收

| 顺序 | 可独立体验的交付 | 放行标准 |
|---|---|---|
| 一 | 一个品种选择器、一个详情视图、一个提问入口 | 目录 33 项均可选择和深链；从 RB 切到 AU 或 I 后，页面、URL、发送请求一致；快速切换、已有草稿、停止和会话回放通过；浏览页面触发零次模型请求 |
| 二 | RB 的期现对照和期限曲线，可直接追问 | 固定公开样本重算基差和跨期；跨日、换月、缺单位均有用例；同一问题从页面和对话取得相同数字与来源；豆粕与股指两个边界样本通过 |
| 三 | 历史复盘、波动与仓单异常 | 按当时可见数据重放事件；同末日不同区间可分别回读；常态、异常、缺报、换月各有样本；先用历史样本核对误报再定阈值 |
| 四 | 持仓风险情景，具备执行数据的品种可评估策略 | 合成持仓核对方向、单位、乘数和成本；缺数据给出具体原因；样本外区间与交易成本可复算 |

前两步通过隔离验收后走正式发布流程，切换后在正式站核对用户流程。后两步可独立迭代。
