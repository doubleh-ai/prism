# Prism 关键设计决定

这些简短记录解释源码设计及其代价，不记录特定实例的部署状态。版本与部署的区别见 [README](../README.md#版本与上线状态)。

## 1. 由 Prism 拥有研究运行器

**决定：整个应用禁止依赖或回退到 Claude Code CLI。** 当前候选的研究对话由 `agent/runtime.py`、`provider.py`、`store.py` 直接管理 HTTP 模型执行；辅助模型也使用相同直接协议，不再保留 CLI 适配器、环境启用开关或磁盘 Skill。Anthropic 兼容 Messages 是接口格式，不是 Claude Code 依赖；DeepSeek / MiniMax 继续保留。

旧链路把模型、工具、进程和报告绑在一个外部运行器中，网页很难区分“进程失败”“资料不足”“模型请求中断”和“结果保存失败”。一个退出码本身也不能定位这些原因。自有运行器让每轮请求、预算、权限、取消、公开事件与结果都有明确归属。

代价是本项目需要维护有限提供方协议、幂等和停止测试。它不是自研基础模型；模型仍由配置的提供方提供推理。新增框架必须解决真实问题，不能只增加依赖与抽象层。

对应代码：[`runtime.py`](../server/agent/runtime.py)、[`provider.py`](../server/agent/provider.py)、[`store.py`](../server/agent/store.py)。

## 2. 网页是主要研究交付物，PDF 是可选产物

**决定：已实现网页报告与研究版本。** 不再要求每轮问答经过旧“白毛”研究 Skill，最终生成 PDF 才算完成。

用户通常需要继续追问、打开引用、看工具快照、比较新旧判断，而不是先下载一份长报告。普通问题允许简答；有研究价值的内容保存为可回看的网页快照，保留原研究边界、证据和缺口。原有文件报告和导出入口继续兼容，但 Native 问答不会声称生成未实际存在的 PDF。

代价是网页需要处理长内容、来源、版本和刷新状态，而不能把布局责任交给生成文件。报告的价值来自可追溯判断，不能由页数、格式或“最终决策”标题保证。

对应代码：[`reports.py`](../server/reports.py)、[`research/ledger.py`](../server/research/ledger.py)、[`app.reports.js`](../static/js/app.reports.js)、[`app.research.js`](../static/js/app.research.js)。

## 3. 对话读者与后台研究分离

**决定：已实现持久事件、只读回放和确认停止。** 浏览器每个问题只提交一次开始请求；刷新和断线读取原任务，不能为恢复显示再次调用模型。

网页连接会断开，但已有工作可能仍在运行。任务表、事件序号和真实资源归属才是事实。停止先登记意图，再等待模型连接、派生工作和最终保存；不能用按钮变灰或 HTTP 返回成功替代后台终态。

代价是需要处理事件重复、缺口、取消竞态和未知状态。默认不会为未知用量失败自动重试，也不会把中断改写成成功。真正的后台任务恢复或重新研究，需要与只读回放分开设计。

对应代码：[`agent/api.py`](../server/agent/api.py)、[`work_lifecycle.py`](../server/work_lifecycle.py)、[`app.chat.js`](../static/js/app.chat.js)。

## 4. 来源和时间是数据，不是报告装饰

**决定：已实现独立研究时点、来源元数据、节选与引用检查。** 优先追溯交易所和公司披露；新闻提供发现线索与交叉对照。来源白名单允许读取，不代表全量数据订阅或访问必定成功。

“今天写的报告”不意味着“今天的数据”。研究观察时间、公开发布时间、采集时间、财报期间和行情交易日必须分开；缺失时不补成现在。搜索片段不能自动变成原文，引用 URL 不应被模型自行改写为另一个看起来更短的链接。

代价是回答可能更明确地显示“未知”“受限”与“待核验”。这是信息边界，不应用虚构数据或来源来填满版面。当前结构和引用检查也不能保证模型已经正确理解全部语义。

对应代码：[`research_context.py`](../server/research_context.py)、[`agent/sources.py`](../server/agent/sources.py)、[`research/ledger.py`](../server/research/ledger.py)、[`agent/prompts.py`](../server/agent/prompts.py)。

## 5. 先验证，再提升知识复用的可信等级

**决定：已实现带边界的历史检索；自动训练和自动事实晋级未实现。** 保存问题、公开答案、证据与版本，让后续研究可以找回原记录；历史结果默认仍是待核验线索。

模型重复一种说法、用户认可或系统保存很多份报告，都不能构成独立事实证据。新研究要保留原时点，并与新的原始材料核对。产业链关系还需区分产品用途、认证、供货、订单和收入传导，写清反方与失效条件。

当前 `knowledge.py` 是账号内的有界文本检索，不更新模型权重，不跨账号共享知识，也没有完整向量索引。以后如需“自演进”，应先建立用户纠正、证据复核、时效检查和固定质量评测，再讨论扩大自动化范围。

对应代码：[`knowledge.py`](../server/agent/knowledge.py)、[`public_text.py`](../server/agent/public_text.py)、[`research/ledger.py`](../server/research/ledger.py)。

## 6. 平台能力逐项迁移，不自动包住旧引擎

**决定：已实现显式原生白名单，专用工作区按实际状态开放。** 对话内工具与页面尽量复用业务调度和记录，但不会把全平台目录全部暴露给模型。

行情查询和已有记录读取，与发起扫描、Astock 或 Vibe 是不同权限与生命周期。当前 Native 不提供这些旧引擎的启动工具，也不自动使用旧 CLI 补位。新增能力要补齐 schema、任务归属、取消、幂等、来源、快照和页面跳转，再显式开放。

代价是短期内页面能力多于 Agent 可用工具。这个差异应在目录中如实展示，不能在产品文案中提前宣称“所有功能都已 Agent 化”。

Astock 仍是可选第三方 Python 引擎；Vibe 新研究与追问固定返回 503，只保留所属历史。独立工作区并不等于已经纳入自有 Agent。

对应代码：[`agent/tools.py`](../server/agent/tools.py)、[`capabilities.py`](../server/capabilities.py)，目录边界见[平台能力](platform-capabilities.md)。

## 7. 应用开源，具体运维私有，运行数据不进 Git

**决定：公开应用与通用交付规范，环境专属运维另存。** 部署所有者应受限管理运维源码、环境配置与实例记录；密钥、数据库、会话、日志、备份及私人历史不得进入 Git 仓库。

可移植性来自清楚的配置接口、固定版本、环境清单和恢复流程，不来自把某台服务器的地址写死进公开源码。研究 Agent 没有生产执行权限。CI、候选打包和 `master` 更新也不直接触发生产切换。

上线必须使用独立可观察流程，保留停止门禁、真实任务排空、加密备份、恢复和兼容回退。取消阻止后续动作，不自动撤销已完成动作；程序回退不静默丢弃新数据库写入。

对应文档：[发布规范](release-process.md)、[发布与介入入口](PROJECT_GUIDE.md#发布停止与回退)。

## 8. 反馈进入工程闭环，不直接变成热修指令

**决定：反馈使用规则分诊和处理台账，可选定期处理单独配置与验证。** 异常先核对版本与复现，再修复、回归、灰度和验证；建议按每日批次统一评审，采纳、暂缓或不采纳都给用户可见理由。`fixed` 必须有验证说明和目标版本，但字段完整不代表已经发布。

自动处理者应由部署所有者单独配置和授权；用户提交的文字是待核实资料，不能授权执行命令、读取凭证、跳过停止保护或扩大部署权限。代价是需要维护真实的处理与发布记录，不能用“自动修复中”掩盖未执行或失败。详见 [反馈闭环](FEEDBACK.md)。

## 9. 旧历史迁入平台，服务路径不依赖旧运行器

**决定：只在显式离线迁移时解析旧 JSONL。** 应用读取 SQLite 的 `legacy_conversation_history`，不再打开外部 CLI 历史、设置或 Skill 目录。导入器只接受预先准备的数据库与历史目录副本，保留公开文本、用户回合数与源指纹；保留现有 SQL 消息和 Native 锚点。源冲突拒绝整次导入。

代价是旧历史需要受控迁移；未迁入时必须明确显示 `pending_import`，不能用静默回读旧目录维持表面兼容。对应代码：[`legacy_history.py`](../server/legacy_history.py)、[`import_legacy_history.py`](../scripts/import_legacy_history.py)。
