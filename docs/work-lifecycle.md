# 任务归属与排空

这是新候选的应用协议说明，不是生产排空证明。旧生产版本没有这套登记；首次升级必须单独解决旧任务保全。真实 Linux 全应用验收、最终候选配对数据库兼容和生产门槛仍分别执行。

## 资源完成的含义

`server/work_lifecycle.py` 为每份工作建立实际归属。调用者超时、断开或收到业务结果，不等于底层资源完成。

| 资源 | 允许结束归属的事实 |
|---|---|
| 异步工作 | 原始所有者完成，全部派生工作收尾 |
| 线程 | 原始 concurrent future 真正完成；取消 asyncio 等待者不会移除它 |
| 子进程 | 实际出生身份一致，原 Popen wait/reap 完成 |
| 需保存的任务 | 派生资源全部完成，可信最终写入及独立读取核验完成 |
| HTTP | 最外层 ASGI 返回，包含流式响应、鉴权和 Activity 收尾 |

HTTP 观察本身不授予派生任务权限。维护期间允许的历史读取、现有问答回应和取消请求，仍计入正在处理的 HTTP。已获准工作的真实 Lease 才能作为父任务；数据库中的旧 token、伪造对象或超时等待者不能创建这种归属。

## 固定生产者

| 类别 | 主应用 | 恢复入口 |
|---|---|---|
| request、market | 启用 | 启用 |
| analysis、scan、cli、auxiliary、capability、diagnostic | 启用 | 禁用 |
| vibe | 禁用 | 禁用 |

扫描取消是协作式的：保留正在执行的真实请求并保存部分结果，再进入终态。市场共用请求在一个调用者断开后仍可完成并写缓存；进程全局 Baostock 会话由真实线程锁串行保护。问答的最终文本和引用、能力任务的最终状态和响应必须完成保存，不能由 SSE 结束推断。

## 状态与失败

1. `running` 接受新业务和已归属的派生工作。
2. `draining` 阻止新业务；继续观察已有任务和允许的 HTTP 收尾，不强制取消或抹去计数。
3. `quiescent` 要求所有生产者已声明，工作、线程、进程、保存与 HTTP 全部为空，且可信本机 adapter 的新鲜递归内核观察符合绑定。
4. `closed` 仅在已证明静默后关闭资源。开发模式只能完成自己的实际 drain/close，不能生成受控 Linux 证明。

无法核验保存、异常取消所有者或未知进程身份会保留 blocked 事实，不能通过重复 seal、等待超时或清空表来变成成功。真实工作变化会使先前观察失效；状态变更需当前 ticket。封存后全部 HTTP 使用纯内存维护 503，避免 nominal read 再访问 SQLite 或记录 Activity。

## Linux 信任边界

`server/work_runtime.py` 只在显式受控模式启用私有协议。root 锁定的固定绑定包含角色、提交、产物摘要、单元和 nonce；端点限制为对应的固定 `/run` 目录。服务核验自身 boot/PID/start ticks/cgroup，先验证 Unix peer 为 root，再解析有界消息。普通客户端不能提交内核证明或取得控制 ticket。

root 监督器仍须独立核验源码/产物、实际单元和进程身份、完整递归 cgroup 及挂载保护。应用复述产物摘要不证明产物真实；单个进程、不存在的 cgroup、绿色 readiness 或应用返回零计数也不单独证明静默。端点替换、身份漂移、未完成资源和未知事实均拒绝继续。

受控启动先处于维护状态。用户旅程要求监督器在外部入口仍受控时显式 resume；验收结束重新 fence/drain/seal。该协议没有任意命令、文件路径、业务参数、凭证输出或 HTTP 管理入口。
