# 界面内容与入口规范

界面围绕用户当前任务组织。功能加入产品后，进入稳定的信息结构；开发批次与新增时间不决定其视觉优先级。

总原则是[从目标出发，由助手辅助完成](product-principles.md)。优先复用已有资料、
减少输入和跳转，只追问必要信息；把相关变化集中预览，避免把每个字段变成一次确认。
保留可选手动操作与真实权限边界，不能为了简化而隐藏操作后果。

## 导航与操作

- 一个功能保留一个主要导航入口。使用现有产品导航和页面分组，不增加功能宣传卡、跨页横幅或重复快捷按钮。
- 工作区侧栏组织当前上下文。账号创建属于账号管理，发布观察属于管理导航；不常驻到其他业务页面。
- 每个表单有明确主操作。次要操作使用普通按钮或链接；不展示始终不可用、没有执行能力的部署或研究按钮。
- 记录入口按实际数据或状态出现。零条记录不占固定区域；读取失败仍提供可见错误和重试路径。
- 产品间切换与产品内部导航分开。Prism 内组织研究，Work 内组织任务和日程；跨产品能力遵循另行确认的产品边界。

## 内容层级

- 页面标题只表达当前任务，避免重复产品名、英文装饰标题、口号、能力数量和新增功能说明。
- 空状态说明下一步即可，使用已有导航和主操作，不重复展示功能广告或能力卡片。
- 研究进度使用一行实时状态，随阶段更新；完成后收起。工具调用与分析过程默认折叠，不把状态事件逐条堆入回答；失败、中断、待补充信息和未知结果仍明确显示。
- 不把开发日志、执行器所在机器、内部模块名或实现原理常驻到业务流程。必要的背景说明进入帮助或可展开详情。
- 状态依据真实观测。未知、失败、过期、未配置和未接入不能被精简成正常；测试或构建成功不能被写成发布成功。
- 研究时间、原始来源、数据缺口、风险口径和操作后果保留在相关数据或操作附近。精简展示不删除这些判断依据。
- 停止入口、权限错误、未保存与提交结果未知等提示必须可见、可操作。账户创建和其他写入保持原有认证、归属与确认要求。

## 验证与维护

使用共享组件、样式和间距；新页面遵循已有产品外壳。修改后检查桌面、窄屏、浅色、深色、键盘操作与焦点。数据读写、历史读取、错误提示和独立停止入口须保持可用。

中文输入法的回车只确认当前字母或候选，下一次主动回车才发送；Shift+Enter
保持换行。检查组合输入结束前后不同的事件顺序，包含缺少输入法标记的回车、
按键释放后的再次发送和失焦恢复。脚本、浏览器输入协议与真实操作系统输入法
验证分别记录，不能互相替代。

PR 应说明清理了哪些重复入口、功能移到哪里，以及实际验证范围。源码和截图通过不表示已经部署。
