- 腾讯：[实际请求](https://qt.gtimg.cn/q=sh600519,sz000001,bj920047)，HTTP 200，抓取于北京时间 20:54:43。
- 字段索引从 0 开始；适配器直接取 `f[6]` 为 volume、`f[37]` 为 turnover。
- AKShare 使用仓库锁定版本 1.18.64，调用真实 `stock_zh_a_daily`，不是模拟数据或东财快照接口。
- 参数：`symbol` 分别为 `sh600519`、`sz000001`、`bj920047`；`start_date=end_date="20261113"`、`adjust="qfq"`。
- AKShare 抓取于北京时间 20:55:18—20:55:22；三个结果的 `date` 均为 `2026-11-13`。
- 该调用与 `AkshareProvider.get_quote` 使用同一接口及复权方式，仅限定取证日期；volume/amount 未作单位换算。
- [AKShare 官方字段说明](https://akshare.akfamily.xyz/data/stock/stock_quote.html)：`stock_zh_a_daily.volume` 为股、`amount` 为元；`turnover` 是换手率，不能与本项目 `Quote.turnover` 混同。

## 结论

- 同日沪深北三个样本均支持：腾讯 f[6] 为手，f[37] 为万元；依据是约 100 / 10000 的实测比例及 f[35] 金额与 AK amount 一致，并非凭字段索引记忆判定。
- AKShare 此接口 volume 为股、amount 为元，符合官方文档；不能推广到 AKShare 的所有接口。
- 在上述修复前基线中，两个 provider 原样映射的 `Quote.volume` / `Quote.turnover` 单位不一致，成交额存在约 10⁴ 倍尺度差异；报价归一化见 [PR #36](https://github.com/doubleh-ai/prism/pull/36)。
- `min_turnover` 实际读取 K 线的 `amount`，不读取报价 `Quote.turnover`；K 线取证及修正见 [PR #37](https://github.com/doubleh-ai/prism/pull/37)。报价样本不能证明 K 线门槛的单位或行为。
- 比例不精确等于 100 / 10000，符合腾讯字段展示精度差异；上表保留差异，没有补齐或改写数值。
- `tests/test_tencent_async.py` 的报价夹具仅 11 字段，不含 f[37]，未覆盖此成交额映射；本 PR 不修改它。
