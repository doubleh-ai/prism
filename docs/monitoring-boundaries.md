# 功能可用性与监测边界

更新：2026-10-30。本文描述本分支的修正，合并或 CI 通过不等于已部署。

## 为什么配置正常仍可能无法使用功能

`/health/ready` 只证明基本服务与数据库就绪。管理页的 `/api/admin/health` 检查本地数据库、Native 入口、工具注册及模型配置格式，不调用模型或业务数据源。模型配置存在不证明认证、余额、网络或回答质量正常。

当前修正将原“总览”明确改为“本地配置检查”，并显示业务验收待验证。异常接口读取失败显示“状态未知”；成功返回空列表只表示未收到未处理记录。网络失败或无效 JSON 不再阻止其他管理面板加载，也不再伪装成零异常。

## 已修正的具体断点

- 个股分析：页面先加载 `app.market.js`，后加载 `app.analysis.js`，旧实现覆盖 Native 入口，仍向已停用的分析接口发请求。现在只保留一个新研究入口：创建独立会话，再调用 Native 对话；移除无效的 2/7 Agent 和 Astock 缓存选项。连续点击不重复启动；旧分析记录仍可读取。
- 研究失败：HTTP 成功接收或回放流，不代表后台研究成功。Native 结束状态保存后，失败与未完成结果现在另外记录诊断事件，管理页与受限反馈诊断接口均可看到分类结果。
- 主动取消不记为异常；预算耗尽、部分完成和非主动的执行中断记为警告。模型认证、连接等失败记为错误。记录仅包含固定错误码，不记录问题、答案、工具正文或模型原始错误。
- 诊断记录失败不会撤销已经保存的研究结果；日志留下固定的诊断不可用标记。该上报是尽力而为，尚无独立诊断存储或可靠投递队列，不能承诺每次异常必达。

## 尚未覆盖

| 范围 | 当前边界 | 后续验收应检查 |
| --- | --- | --- |
| 真实模型 | 配置检查与运行失败记录 | 专用合成账号的完整研究、保存与回放 |
| 行情与基本面 | 请求失败及部分页面诊断 | 数据时点、单位、财报期间、缺失字段及来源 |
| 图表和报告 | 少量空白与对象渲染规则 | 响应式布局、溢出、表格、引用和长报告 |
| 指标与选股 | 原有请求记录 | 结果计算、任务终态、失败覆盖率和回读 |
| 深度研究 | 历史只读，新执行停用 | Native 替代流程独立实现与验收；停用不可显示为业务可用 |
| 反馈自动处理 | 接口与诊断分类 | 云端处理者身份、最后成功巡检、队列积压与写回 |

下一阶段看板应按能力区分可用、退化、故障、停用、未验证，并显示证据来源、最后检查时间、有效期及版本。未执行的检查不能显示为通过；一次人工检查不能改称持续监测。业务探针必须有独立预算和合成身份，不能在打开管理页时隐式启动付费研究或全市场扫描。

## 本分支验证

- 使用页面实际脚本顺序的前端回归覆盖 Native 个股入口、防重复与历史选择竞态，以及管理诊断的 HTTP 失败、断网、无效 JSON 和空记录。
- 隔离 Native 运行器验证模型认证、超时与连接失败进入诊断，主动取消不报警，重复结束不重复计数，诊断写入故障不改变已保存终态。
- 未将真实用户反馈、账号会话或运维源码写入本文件。本分支不新增生产修改或部署步骤。
