# 节选与结论的自动复核

Native Agent 登记重要结论后，可以在同一研究预算内，用独立上下文核对节选与表述。
用户继续提出研究目标，结果进入原有证据详情和知识记录，不增加表单或入口。
本能力属于 v0.23.0 候选源码，真实模型质量和部署仍须单独验收。

## 材料与判断

复核包仅包含本轮结论、服务器取得且带正文摘要的资料节选、日期、链接及范围，
不传完整会话、研究偏好、持仓明细、私人 Work 内容或其他账号资料。搜索摘要和
没有服务器正文摘要的工具文本不能代替已取得的原文节选。

复核使用当前研究选择的直接 HTTP 模型，另建上下文，关闭工具和搜索。检查主体、
产品、期间、单位、统计口径、否定词、商业阶段及相反证据。最多六条结论，按输出
预算缩小窗口；每条最多两份支持和一份反方节选。省略范围明确保留，不自动把部分
支持升级为整体结论已获证实。

回复必须逐项绑定实际结论ID和本轮段落ID。未知ID、额外授权字段、重复字段及
不完整 JSON 会拒绝，不修补或重试。仅校验后的意见和材料绑定摘要进入记录；
原始回复、私有模型续接及推理内容不作为复核结果保存。

## 预算与停止

每轮最多启动一次复核，计入原有次数、输出、时间及每日配额，不增加上限。需要
留有后续回答的调用余量、足够输出及至少75秒时间；复核自身最多30秒。每日配额
不足两次时，优先跳过复核并收尾。并发仍可能消耗共享配额，每次真实请求都须再次
通过原有准入检查。

同一真实任务、停止信号和账号权限约束复核。失败、超时、无效回复或预算不足
分别保留，已有资料和回答继续保存。失败或未知用量不退回、不清零；后续回答
是新阶段，不是重试复核。重启后未结束的复核标为中断及用量未知，不静默恢复。

认证失败、供应商限流和配置/输入错误会停止后续模型请求，不再向同一服务请求收尾。
格式无效、局部复核超时或暂时不可用时，仍可在原预算内给出带缺口的后续回答。

## 怎样理解结果

`model_review` 区分未执行、运行中、完成、无效、失败及取消。意见分为节选支持、
部分支持、不支持及证据不足，保留原因和未复核数量。后续新增结论不继承先前复核。
冻结报告保存当时快照，重复保存不覆盖历史。

“完成”只表示完成这次协议化复核，不表示判断正确。它不验证完整原文真实性或
来源独立性，也不改写结论、人工复核、争议或撤回状态。知识条目仍按候选和人工
复核规则使用，数字相容或模型同意不能代替独立事实认证。

正文旁只提示待核查项，具体意见沿用证据详情。人工记录与自动意见分别标明。

产业分析复用结论时一并保留这些意见。支持材料出现部分支持、不支持或证据不足时，
先回查已有节选，不把该关系自动拼入传导链；人工复核记录不被修改。未执行、失败、
未覆盖的新增结论分别保留缺口。自动意见为支持也只保留为待核验假设，不能认证供货
或商业兑现。详细原因放在既有“证据与限制”中，不增加入口或要求用户逐条操作。

## 开发与验收

`server/research/model_review.py` 管理材料、封闭回复校验及记录，
`server/agent/runtime.py` 管理唯一 HTTP 调用、预算、实际取消及用量。
没有新工具权限、模型自动切换、外部 CLI 或 Skill 后备执行。

脚本模型回归验证的是执行机制。真实模型仍须用固定标注样例，分别核对错误支持、
遗漏反证、时间口径与样本外效果，记录实际结果与用量后，才可声称对应质量验收通过。
