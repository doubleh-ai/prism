# 节选与结论的自动复核

Native Agent 登记重要结论后，可以在同一研究预算内，用独立上下文核对节选与表述。
用户继续提出研究目标，结果进入原有证据详情和知识记录，不增加表单或入口。
本页描述 v0.24.0 开发候选，真实模型质量和部署仍须单独验收。

## 材料与判断

复核包包含本轮结论、服务器取得且带正文摘要的资料节选、日期、链接及范围，
以及本账号仍可用、与当前主体和具体指标相关的有限历史结论及其原始节选，
不传完整会话、研究偏好、持仓明细、私人 Work 内容或其他账号资料。搜索摘要和
没有服务器正文摘要的工具文本不能代替已取得的原文节选。

复核使用当前研究选择的直接 HTTP 模型，另建上下文，关闭工具和搜索。检查主体、
产品、期间、单位、统计口径、否定词、商业阶段及相反证据。最多六条结论，按输出
预算缩小窗口；每条最多两份支持和一份反方节选。省略范围明确保留，不自动把部分
支持升级为整体结论已获证实。

回复必须逐项绑定实际结论ID和提供的段落ID。历史比较另绑定所给历史结论ID。
支持或部分支持必须引用本轮已登记的支持段落，不能仅凭反证给出支持。
历史一致或潜在冲突还须引用每条历史判断原本的支持段落，不能以其反证替代。
遗漏本轮或历史上下文中已提供的反方节选时，系统保留模型原始意见，但将整体支持
范围标为未核全；模型给出的“支持”只按部分支持呈现。保存时重新计算，不能通过
提交一个完整支持标签绕过。引用所有材料仍不证明模型理解正确或事实成立。
新流程读取旧规则产生的意见时，使用已保存的方法摘要识别版本，提示需重新复核；
旧意见不能充当当前规则下的完整支持。原始记录和冻结报告保持原样，不批量改写历史。
方法摘要同时绑定提示与引用规则版本；维护者改变裁决规则时须更新方法版本及样例。
未知ID、额外授权字段、重复字段及
不完整 JSON 会拒绝，不修补或重试。仅校验后的意见和材料绑定摘要进入记录；
原始回复、私有模型续接及推理内容不作为复核结果保存。

## 历史观点对照

Agent 登记新判断后，系统在原有复核中对照历史，用户无需选择比较记录。
只有单个主体、具体指标、明确期间与口径均已登记的判断进入匹配；不猜测实体别名
或把不同产品归为同一指标。同期间、同口径的差异优先，期间或口径不同只能作为
背景变化，不能标为同口径矛盾。同一正文反复引用明确标记，不作为独立佐证。

历史候选只来自当前账号仍可访问的研究。过期、争议、撤回、替代、已删除会话、
晚于本轮信息截止的研究或结论登记时间，以及没有实际正文摘要的资料不参与。
缺少可核对登记时间的旧判断也不自动补作历史依据。重复相同表述在结果窗口
之前排除；扫描限时、候选窗口、每条最多两份历史上下文和总量上限仍保留覆盖缺口，
不声称遍历或核验了全部历史。历史上下文需要额外输出时缩小本次复核窗口，不增加
请求或输出预算。

意见区分表述相容、背景变化、潜在矛盾与证据不足。相容或矛盾必须绑定双方实际节选；
潜在矛盾、证据不足或材料省略时，不能获得整体支持状态。原因回到原有证据详情与
后续回答，历史观点始终保留候选或人工状态，不自动改写旧报告。

请求前和保存意见时重新检查历史内容、正文摘要与复核版本。材料已变化时跳过或
作废相应复核，不自动重试。只保存材料绑定摘要和自动意见，不复制整份历史原文、
会话问题或人工复核备注；之后撤回或删除来源仍提示依赖该判断的研究。

## 预算与停止

每轮最多启动一次复核，计入原有次数、输出、时间及每日配额，不增加上限。需要
留有后续回答的调用余量、足够输出及至少75秒时间；复核自身最多30秒。每日配额
不足两次时，优先跳过复核并收尾。并发仍可能消耗共享配额，每次真实请求都须再次
通过原有准入检查。

同一真实任务、停止信号和账号权限约束复核。失败、超时、无效回复或预算不足
分别保留，已有资料和回答继续保存。失败或未知用量不退回、不清零；后续回答
是新阶段，不是重试复核。重启后未结束的复核标为中断及用量未知，不静默恢复。

认证失败、供应商限流和配置/输入错误会停止后续模型请求，不再向同一服务请求收尾。
格式无效、局部复核超时或暂时不可用时，仍可在原预算内给出带缺口的后续回答。

## 怎样理解结果

`model_review` 区分未执行、运行中、完成、无效、失败及取消。意见分为节选支持、
部分支持、不支持及证据不足，保留原因和未复核数量。后续新增结论不继承先前复核。
冻结报告保存当时快照，重复保存不覆盖历史。

“完成”只表示完成这次协议化复核，不表示判断正确。它不验证完整原文真实性或
来源独立性，也不改写结论、人工复核、争议或撤回状态。知识条目仍按候选和人工
复核规则使用，数字相容或模型同意不能代替独立事实认证。

正文旁只提示待核查项，具体意见沿用证据详情。人工记录与自动意见分别标明。

产业分析复用结论时一并保留这些意见。支持材料出现部分支持、不支持或证据不足时，
先回查已有节选，不把该关系自动拼入传导链；人工复核记录不被修改。未执行、失败、
未覆盖的新增结论分别保留缺口。自动意见为支持也只保留为待核验假设，不能认证供货
或商业兑现。详细原因放在既有“证据与限制”中，不增加入口或要求用户逐条操作。

## 开发与验收

`server/research/model_review.py` 管理材料、封闭回复校验及记录，
`server/research/history_review.py` 在实时归属和来源边界内选择历史对照，
`server/agent/runtime.py` 管理唯一 HTTP 调用、预算、实际取消及用量。
没有新工具权限、模型自动切换、外部 CLI 或 Skill 后备执行。

脚本模型回归验证的是执行机制。真实模型仍须用固定标注样例，分别核对错误支持、
遗漏反证、时间口径与样本外效果，记录实际结果与用量后，才可声称对应质量验收通过。

### 固定节选样例

`tests/research_quality_corpus.py` 提供十二个合成样例，覆盖商业阶段、否定词、预测与实际、
单位、主体、期间、成交持仓与资金流、部分支持、相反资料、网页指令及历史观点变化。
准备函数将它们分为六组，每组两条结论；预期答案及标注理由不会进入模型材料。
这份样例只测试给定节选与表述的关系，不取代原始来源、完整研究或样本外质量评估。

评分同时使用实际复核协议解析器和独立标注，检查原始意见、有效支持范围及历史比较。
错误主体、期间或单位的结论即使引用了真实段落ID，也不能仅因回复格式正确而通过。
缺失、无效、重复或绑定到其他样例的回复分别拒绝或记为未完成；一律给出支持的基线
会被检出。结果不包含原始模型理由，也不自动认证提供方身份或生产状态。

`pytest tests/test_research_quality_corpus.py tests/test_review_counterevidence.py` 验证的是
评分器和引用保护机制，不调用模型。真正运行样例须在独立隔离环境、固定源码及新的
有限模型许可下进行，并保留真实调用与用量证据；不能把合成答案的通过记录改标为
真实模型通过，或将真实模型回复直接提交到公开仓库。
