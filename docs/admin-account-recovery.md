# 管理员账号与邮箱找回

本页描述代码能力和启用条件，不代表已部署或真实邮件投递已验收。

## 使用方式

- 登录页及管理看板的「账号控制」提供「管理员邮箱找回」入口。
- 平台保存密码哈希，无法查看原密码。已有的管理员为普通用户重置密码功能继续保留。
- 忘记管理员密码时，申请验证码，到事先绑定的个人邮箱查收，输入验证码并两次输入新密码。
- 重置成功后撤销该管理员所有旧会话，再到登录页使用新密码登录；不会自动登录。
- 本版只恢复一个事先配置的管理员。普通用户邮箱自助找回、多管理员各自绑定邮箱、通行密钥及重置成功邮件通知尚未实现。
- 页面显示「尚未启用」意味着还没有完整配置，不能当作发信成功；邮件服务接受发送也不等于已进入收件箱。

## 为什么不提供查看密码

bcrypt 密码哈希不能还原密码。为了能够查看而增加明文或可逆密码存储，会扩大数据泄漏的影响。邮箱验证后设置新密码即可解决遗忘问题；用户也可以用浏览器或系统密码管理器保存自己的密码。

## 邮箱与发信配置

收件邮箱与平台发件地址是两个角色：收件邮箱应由管理员长期掌控；平台使用专门发信子域，例如 `no-reply@notify.example.com`。无需自建邮件服务器。

第一版采用腾讯云 SES 模板 HTTP API，固定目的地 `https://ses.tencentcloudapi.com/`。新账号默认需审核模板，示例模板变量仅为 `code`：

> 你正在重置 Prism 管理员密码。验证码：{{code}}，10 分钟内有效。不要转发验证码。如果不是你操作，请忽略本邮件。

具体模板占位格式以服务商控制台为准。请先验证独立发信子域，按服务商要求配置 SPF、DKIM、DMARC 等 DNS 记录并创建发件地址、审核模板。新开通的腾讯云个人账号可能无法使用 SMTP，本实现不依赖 SMTP。

配置仅通过私有运维流程提供，不能放入开源仓库、PR、前端或诊断导出。管理员收信邮箱的首次绑定及更换必须由站点所有者明确确认；现存登录会话不能绕过这一步。

| 环境变量 | 用途 |
| --- | --- |
| `PRISM_ADMIN_RECOVERY_ENABLED` | 仅值 `1` 启用，默认关闭 |
| `PRISM_ADMIN_RECOVERY_USER` | 已存在且启用的管理员用户名，须属于管理员名单 |
| `PRISM_ADMIN_RECOVERY_EMAIL` | 所有者确认的收件邮箱，匿名请求不能指定或修改 |
| `PRISM_ADMIN_RECOVERY_SENDER` | 已验证的专用发件邮箱 |
| `PRISM_ADMIN_RECOVERY_TEMPLATE_ID` | 已审核的验证码模板 ID |
| `PRISM_ADMIN_RECOVERY_REGION` | `ap-guangzhou` 或 `ap-hongkong`，与邮件资源地域一致 |
| `PRISM_ADMIN_RECOVERY_SECRET_ID` / `PRISM_ADMIN_RECOVERY_SECRET_KEY` | 仅允许发信操作的专用云凭证，私有保存 |

不得使用云主账号的广泛权限凭证。不以任意 HTTP URL、收件地址或邮件正文作为访客参数。当前没有自动开通付费服务或修改 DNS 的功能。

## 安全与边界

- 验证码为 8 位随机数字，有效期 10 分钟，最多错误尝试 5 次。另有不可猜测的申请标识，保留在当前页面内存中。刷新后需重新申请。
- 数据库只保存 HMAC 校验值，不保存验证码、原密码或邮箱凭证。校验绑定账号、收件邮箱及当前密码哈希，修改任一项都会使旧申请失效。
- 每分钟最多 1 封、每小时 6 封、每天 12 封，发送失败仍占额度；匿名入口可能被恶意占用额度，所以不能替代独立维护恢复渠道。登录不因验证码输错而锁定。
- 邮件请求超时、拒绝、异常响应或重定向均不能视为成功。本次验证码作废，不自动重试；即使迟到邮件进入邮箱，也不能使用该码。
- 新密码至少 12 字符，最多 72 UTF-8 字节，必须二次确认；不会通过邮件发送新密码。
- 重置、单次消费、撤销会话在同一数据库事务完成；禁用账号不会被恢复为启用状态。并发登录在创建会话前重新核验密码版本，避免重置后旧密码生成新会话。
- 身份验证只证明控制了绑定邮箱；邮箱被盗同样可能危及账号。应为收信邮箱启用多因素验证。
- 只记录固定事件名和请求状态，不记录密码、验证码、邮件正文或云错误原文。匿名状态接口不公开账号及邮箱。管理员状态接口只返回掩码邮箱和配置状态。
- 申请和重置仍经过现有 CSRF、任务准入与维护保护；维护期间不旁路数据库写入。回退前按实际数据库兼容性验证，不删除恢复表或还原用户数据。

## 验收与上线

本地测试使用合成账号、隔离数据库与模拟邮件传输，覆盖重放、过期、错误次数、禁用账号、并发登录/重置、事务回滚、服务商失败以及无凭证页面。它们不证明真实邮箱投递成功。

上线前必须完成：所有者确认收件邮箱及服务商、私有配置、模板和域名认证、受控测试邮箱实际接收、合成账号重置及旧会话失效验证。切换仍使用私有固定候选控制器，保留停止入口、生产写锁、任务保护及加密备份恢复检查。
