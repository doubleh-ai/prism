# 产品与体验

状态：目标设计；本批仅交付功能旗标下的个人任务预览。不要把下面的场景清单当作实现清单。

## 用户应当感受到什么

打开平台后能回答三个问题：我今天要做什么、哪些事情有风险、下一步可以做什么。自然语言和普通界面是同一套业务的两种入口，用户不需要为了完成任务先学会与 Agent 对话。

研究结果应该可以追问、核对、纠正和继续使用；工作结果应该可以执行、跟进和回顾。页面数量、报告长度、自动化次数不是质量指标。

## 入口与导航

登录后进入上次明确选择的工作区，首次使用给出研究 / 工作选择。选择只改变入口，不允许跨工作区读取数据。

| 区域 | 一级入口 | 主要操作 |
|---|---|---|
| 统一入口 | 最近工作、需要关注、工作区切换 | 回到原记录，选择自己的工作上下文 |
| Prism | 研究对话、研究记录、市场与资产、产业关系 | 提问、核对证据、比较版本、继续研究 |
| Work | 今日、任务、日历、项目、会议、回顾 | 安排、执行、更新、跟进、整理 |
| 控制台 | 运行、异常与反馈、模型连接、发布记录 | 查看真实状态；受限配置；跳转独立人工介入入口 |

旧报告、旧对话和现有研究入口保持可访问。未完成能力不出现在可点击导航中，或者明确标注尚不可用；禁止用静态占位页伪装已接通流程。

## Work 的对象关系

- **项目**记录目标、范围、验收标准、里程碑、交付物、负责人、依赖与风险。
- **任务**记录要完成的事情、当前状态、优先级、截止时间和完成依据。
- **日程**记录一段占用时间；给任务安排时间不等于完成任务。
- **会议**记录议题、公开记录、决定、行动项及与项目的关系。
- **回顾**是上述记录在某时点的快照，区分计划、实际、阻塞和未知。

首版个人任务状态为 `todo / doing / done / cancelled`，取消不是删除。后续团队分工以项目成员权限为前提；不能通过一个“负责人”自由文本字段绕过成员边界。

### 一条完整的工作流程

1. 手机上快速记录事项，显示“已保存”或“尚未保存”，网络结果未知时保留原提交标识。
2. 电脑上整理为任务，设置优先级与截止时间；两端同时修改会显示冲突，不覆盖新版本。
3. 把任务拆入项目，查看前置依赖，安排进日历。截止日期和计划占用时间分别展示。
4. 会议后把决定和行动项写回原项目，用户确认负责人、时间及通知对象。
5. 云端执行已授权提醒，站内可查看成功、失败、未知和取消状态。
6. 周报引用真实任务与会议记录；没有进展记录的事项标为待确认，不能自动记成完成。

## Agent 的体验

Agent 可以根据权限查询、解释、提出方案和执行获准动作。例如“下周五交方案，帮我拆任务并排时间”，应先给可编辑方案、冲突与假设，再展示具体变更。

| 动作 | 默认体验 |
|---|---|
| 查询自己的任务、日程、公开研究来源 | 当前上下文内直接执行，显示实际记录链接 |
| 新建或修改任务、调整日程 | 展示提案与变更，获准后执行；可授权有限范围规则 |
| 通知他人、邀请会议、向第三方发送材料 | 明示目的端、内容、收件人和范围，单独确认 |
| 删除大量数据、生产维护、恢复数据 | 不由普通研究 / Work Agent 执行，进入对应受控流程 |

审批后若对象版本、权限、提案内容或目的端改变，原审批失效。模型文字不能宣布动作成功；卡片必须显示实际动作 ID、业务版本和结果。刷新只是重新读取执行记录。

## Prism 的专业研究流程

先判断问题需要简答、专题研究还是持续跟踪，不强制每轮生成长报告。网页是主要交付物，PDF 是可选导出。

研究依次保存：问题与研究时点 → 资料和时间 → 主张与反证 → 推导及计算 → 情景与风险 → 可回看的版本。来源等级、取得方式和是否核验原文分别展示，不用来源品牌代替事实核验。

优先使用交易所与公司公告；财联社、金十数据、新浪财经可用于线索与交叉核对。是否允许技术访问、是否完整取得、是否有使用许可、是否及时更新是独立问题；不能因为加入名单就声称有完整实时数据。

产业链从节点列表升级为有证据的关系：产品用途、认证、供货、订单和收入影响分别建模，记录容量、替代性、地域、时间、反证及失效条件。未知关系不能补成已确认供应链。

### 用户画像

画像由用户明确编辑：风险偏好、期限、可接受回撤、集中度、流动性要求、允许资产与杠杆约束等。敏感金额可不填写。每轮研究冻结当时画像版本，历史报告不随新设置静默改写。

激进与保守可以改变情景排序和风险表达，不能改变事实、来源等级或用户的硬性限制。系统推测只能作为待确认建议，不能私自变更画像。投资偏好不得影响工作排期或 Work 记忆。

不填写资金或持仓时，集中度、杠杆和实际损失约束显示“未评估”，仍可提供明确假设的情景。已评估项目可以展开查看画像版本、持仓 / 市场快照时点和计算依据；不把缺失输入显示为风险已通过。

### 从研究转为跟进

用户可以选择某份研究中的具体结论或待核验事项，预览要复制的任务标题、说明、截止时间和来源链接，再选择自己的 Work 工作区。创建成功后两端显示同一个交接记录。来源链接继续按原研究权限访问；共享撤回后显示不可访问。明确复制到任务中的文字属于目标记录，确认页说明其保留方式，不假装可以远程收回所有副本。这个流程不开放 Work 对全部研究历史的检索。

## 跨端与可访问性

- 桌面：信息并排、键盘操作、清晰焦点与快捷录入；拖拽只是可选操作，必须有按钮等价路径。
- 手机：今日、收集、提醒、完成任务优先；不缩小桌面多栏；320px 起不横向溢出。
- 平板：按实际可用宽度组织日历和任务详情，不按设备品牌判断布局。
- 主题：浅 / 深色使用成对颜色令牌；状态同时有文字，不能只靠颜色。
- 所有重要动作显示保存状态和可理解的失败说明；用户输入不以 HTML 注入页面。

网页优先，渐进增加可安装能力。通知能力按浏览器实际支持和用户授权判断；iPhone 的主屏幕 Web App 通知有独立条件，不能承诺普通网页标签页始终可靠推送。参考 [WebKit 官方说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) 与 [PWA 能力](https://web.dev/learn/pwa/progressive-web-apps)。

Work 首批只使用静态资源缓存，不把工作正文或访问令牌写入持久浏览器缓存；未发送草稿保留在当前页面并提示离开风险。现有 Prism 仍有账号键控的 IndexedDB 对话缓存，这不是 Work 的离线存储；统一隐私策略落地时需要单独迁移、清理并验证，不能宣称已经全站禁用私人缓存。后续离线草稿须独立设计设备信任、账号切换、清理和同步冲突。版本更新不能强制刷新正在编辑的窗口。

## 反馈和自演进

所有主要页面有清楚的反馈入口，提交后可查看处理进度与对应修复版本。异常、改进建议和内容纠正分别处理。

异常进入复现、诊断、修复、验证、灰度流程；建议每天统一评审，给采纳、暂缓或拒绝理由；内容纠正进入证据复核，不直接训练模型。自演进的成果应体现为可验证的改进记录，不能用“学习中”掩盖未执行或失败。

## 体验验收

首批任务至少验证：手机创建电脑读取、重复提交不重复创建、旧版本更新冲突、账号隔离、明确时区、断网结果未知、取消后记录保留、版本升级不打断编辑。320 / 390 / 768 / 1440px、键盘和触屏均需要实际界面检查。

后续日历验收包含夏令时跳时 / 重时、全天事项、重复例外、跨时区显示及冲突；云提醒验收包含 Mac 离线、worker 重启、过期租约、未知投递和可见取消。周报的每项完成结论必须能打开对应依据。
