# 迁移、验收与受控交付

状态：执行计划；没有一项勾选能替代相应的实际证据。本文件不包含实例运维命令或地址。

## 总体推进规则

保留现有功能与数据，通过独立工作区和逐项服务替换推进重构。旧行为若本身不可靠可以重设计，但必须有明确迁移、用户说明与回退策略。保护线上未同步成果；禁止用整目录覆盖或从旧 Git 历史直接执行来获得表面兼容。

既有 Native 发布目标仍有实际验收缺口，新目标在其后持续推进。隔离开发可并行，生产切换必须以当前固定候选为对象重新验收。发生严重旧故障时先有界修复，不等整个平台重写。

| G3 Agent 与研究质量 | 工作区工具 / 知识、有限写提案、画像、资产引擎合同和期货试点 | 越权、授权过期与对象漂移、引用和时间、画像版本、股票 / 期货独立口径、固定质量集 | 存过就核验通过、期货完整覆盖 |

每阶段可以拆成多个可独立灰度的 PR；任何单个 PR 都应带来可操作的用户路径，避免长时间只堆框架和占位页面。

## 第一批实现合同

新代码位于 `server/productivity/`、`templates/work.html`、`static/css/work.css`、`static/js/app.work.js`。入口为 `/work` 和 `/api/work/*`，由 `PRISM_WORK_ENABLED=1` 显式开启；默认关闭，不改变现有部署行为。

首批只实现个人 workspace、任务创建 / 查询 / 更新、版本冲突和有限变更记录。GET 不创建 workspace；首次使用由用户明确启用。取消任务保留记录。不开放团队、日历同步、推送、Work Agent 或模型调用。

| 接口 | 目的 |
|---|---|
| `GET /api/work/overview` | 读取个人工作区与有界任务；无工作区时返回空状态 |
| `POST /api/work/spaces` | 明确创建个人工作区；固定请求 ID 去重 |
| `GET /api/work/spaces/{id}/tasks` | 账号内列表、状态与有界游标 |
| `POST /api/work/spaces/{id}/tasks` | 原子创建、去重与审计 |
| `GET /api/work/spaces/{id}/tasks/{task}` | 账号内详情与有限历史 |
| `PATCH /api/work/spaces/{id}/tasks/{task}` | 按 expected_version 更新，冲突拒绝 |

接口不得接受 owner 或任意成员配置。日期时间必须明确 offset 与有效 IANA 时区；对未支持的时间语义明确拒绝。任务数据不进入浏览器持久缓存、公开日志、Git 或模型。

## 数据迁移

1. 固定源、目标 schema、候选和迁移脚本摘要；在加密备份恢复出的隔离副本验证。
2. 映射旧账号、会话、研究、报告、画像和知识；保留原 ID / URL 或提供稳定映射，不重新生成所有主键。
3. 将旧研究映射到各账号的研究 workspace。后续团队共享不能把全部个人历史自动公开。
4. Work 初批使用新表和清楚的账号清理规则。当前复用同一 SQLite 文件以保证原子权限和清理；这是逻辑隔离，不是物理安全隔离。将来拆库必须解决事务和一致性，不可只改连接字符串。
5. 对比每张旧表的结构、全部保留行、类型、关键关联与序列；仅允许列出的迁移变化，不能排除整张表来掩盖差异。
6. 对旧任务、历史导入、会话撤销、保留期清理分别定义预期；不把所有启动变化混成一个“数据库通过”。
7. 验证删除、停用、导出、检索、缓存与 worker 写入的权限一致性。
   现有研究 IndexedDB 对话缓存须单独盘点、迁移与清理；不能把 Work 不写私人缓存当作全站旧缓存已清空。
8. 迁移失败保持原始副本与回执，生产不继续；重新生成源指纹不能洗掉漂移。

扩大 schema 后，旧恢复版不一定理解新字段或清理新数据。每次必须用实际兼容恢复候选验证，不把“新增表看起来无害”当证据。首批功能旗标关闭时不建新表；开启后产生的数据即使关闭旗标也要保留并纳入备份。

## 自动化与 Mac 的分工

工程变更表保存任务、基准提交、分支、负责者、代次和执行状态。Mac 开发有明确优先权，云端不覆盖未提交成果；云端可独立诊断并提交修复提案。冲突进入评审，禁止自动强推或改写发布历史。

异常自动处理流程：收集最少诊断 → 核对版本和影响 → 隔离复现 → 有界修复分支 → 回归与独立检查 → 固定候选 → 灰度 → 真实用户路径验证 → 回写反馈。任何失败保留原因与当前阶段，不把提交代码等同解决用户问题。

建议每天按用户时区 / 约定评审时区形成批次，去重后记录采纳、暂缓或拒绝的理由。需求文字只作为材料，不能授权执行代码。定时任务配置和实际成功运行是两项证据。

## 验收分层

- **合同与单元**：领域不变量、字段 / 权限、时间与状态转换。
- **实际数据库**：事务回滚、并发冲突、幂等、跨账号与删除；不只模拟 SQL 返回值。
- **界面运行**：实际脚本、焦点、错误、表单、结果未知与页面重载；不得仅以字符串快照验收交互。
- **跨端旅程**：实际浏览器在 320 / 390 / 768 / 1440px 操作；刷新、重登录、两端更新和静态版本更新。
- **后台与集成**：真实 worker 进程重启 / 取消 / 过期租约、实际隔离网络和文件系统；外部集成单独限定验收。
- **模型质量**：固定合成问题和人工可核对证据；具体提供方、内容、额度和窗口另获需要的明确许可。不复用过期许可，不自动重试未知用量。
- **发布**：停止门禁、备份恢复、任务排空、切换、实际修订与用户路径、恢复开放。

数据库测试、模拟模型、健康检查、CI 和源码 PR 分别记录。它们都不能替代真实部署或业务质量证明。

## 发布与恢复

应用开源；实例运维源码与无凭证配置保存在私有 ops；凭证与运行数据存于私有密钥 / 数据系统；旧 Git 历史离线保留。公开 PR 和文档只写通用行为、无隐私复现和必要验证。

实际发布只使用审查过的私有控制器和不可变候选。独立发布记录必须能在应用不可用时查看，包含摘要、操作者、环境、起止、阶段、失败 / 未知、停止和实际恢复状态。

切换前确认：当前源与运行身份、未同步成果保护、当前候选的隔离与业务验收、兼容恢复版、加密备份与实际恢复、受控 admission hold、真实活动工作排空、独占发布者和独立停止信号。

停止阻止后续边界，不自动撤销已经发生的动作；连接中断要对账实际状态。代码 / 环境回退不自动回滚数据。会丢弃新写入的数据恢复需要具体损失窗口与单独授权。

只在实际服务修订、关键流程和恢复开放均通过后标记上线成功；之后同步公开 `master`、版本文档和用户可见变更，分别记录源码合并与生产发布时间。

每个领域维护：用途与非目标、数据归属、入口与配置、错误分类、权限、迁移、测试、可观察字段和已知限制。变更清单链接具体代码和实际验收记录。让维护者可以从产品问题定位到对象、任务、代码和版本，不依赖某一次对话或某个人的记忆。
