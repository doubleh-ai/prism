## 产品组成

- **DoubleH**：统一网站入口、账号、工作区切换、通知和偏好。
- **Prism · 研究**：股票与后续期货研究、证据、产业链、情景和用户风险画像。
- **Work · 工作台**：今日、任务、日历、项目、会议与有依据的回顾。
- **控制台**：管理员查看云端任务、异常、模型配置和发布进度。生产执行权属于独立私有控制面。

这些名称是产品组织决定。初期不强制重命名公开仓库，不一次性迁移域名，不让现有研究链接失效。

## 能力状态账本

状态必须用“设计 / 开发 / 本地验证 / 服务器验收 / 灰度 / 已发布”描述；每次更新附实际证据。下表不是生产可用性清单。

| 能力 | 本分支起点 | 本批交付范围 |
|---|---|---|
| Native 研究与账号内研究记录 | 继承固定候选源码，实际生产验收未在本文确认 | 保持行为，回归保护 |
| Work 个人工作区与任务 | 无 | 独立 `/work` 预览、私有任务、版本冲突、去重、有限审计 |

| 独立投资画像 | 设计 | 后续显式编辑、版本冻结与隔离验收 |

## 当前执行顺序

1. **G0：关闭现有 Native 发布的实际验收缺口。** 保留失败与未知记录，完成真正的业务往返、兼容、备份恢复和获准模型验收。
2. **G1：统一平台基础与 Work 个人任务。** 独立分支、功能旗标、只操作隔离数据；用户先能完成一条真实工作流程。
3. **研究与可靠性轨：与 G1 并行。** 优先改善研究显示、来源和时间、用户画像、反馈进度及只读运行观察。每项形成独立用户流程与验收出口，不等 Work 日历或项目完成。
4. **G2：日历、项目和会议贯通。** 再接云端提醒和可追溯回顾，验证 Mac 离线运行。
5. **G3：工作区 Agent 与知识贯通。** 在权限贯通后开放有限写入提案、跨模块显式交接和股票 / 期货专用流程。研究质量和画像的独立交付不以整个 G3 完成为前提。
6. **G4：云端工程闭环。** 在已可见的反馈和运行记录之上，落实修复分支、每日建议评审、Mac 仲裁、模型路由与运营控制台的受限执行。

G1 可在隔离环境与 G0 并行开发；不得以新目标为理由跳过 G0 的停止保护或向未验证应用开放线上数据。阶段之间依据验收结果推进，不以日历承诺替代完成事实。

阶段编号表达依赖范围，不是把所有研究改进排在全部办公功能之后。首个稳定基线之后，研究与可靠性、Work 个人工作流两条轨各自固定候选、验证和灰度；涉及共同身份、数据库或发布控制的改动才合并安排兼容验收。
