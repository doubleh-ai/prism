# 下一代平台设计决定

状态：2026-10-27 目标设计；落实状态见 [状态账本](README.md)。已有 Native 决定仍见 [DECISIONS](../DECISIONS.md)。

| 决定 | 理由 | 代价 / 重新考虑条件 |
|---|---|---|
| DoubleH 统一入口，Prism 与 Work 独立工作区 | 保留研究定位，工作管理有自己的信息结构 | 需要贯通权限，不能只加一个切换按钮 |
| 模块单体 + 独立 worker | 先利用现有受测服务，降低一次性迁移风险 | 出现明确资源 / 安全 / 团队边界后可拆服务 |
| 继续自研 Native，无 Claude Code 后备 | 平台拥有工具、预算、状态和停止能力 | 自己维护协议与验收，不等于自研基础模型 |
| 页面与 Agent 共用业务服务 | 直接操作与自然语言结果一致、可追溯 | 写动作需要版本、授权和幂等合同 |
| 工作区先于全平台知识共享 | 避免工作、投资与不同项目记忆串用 | 迁移完成前不开放 Work 知识工具 |
| 网页结果优先，PDF 可选 | 方便追问、引用、版本和移动查看 | 需要认真维护网页长内容与证据体验 |
| 知识积累先核验、后晋级 | 保存与重复不是事实证据 | 允许明确的未知、过期和待核验 |
| 风格画像显式、可改、版本化 | 每个用户的情景和约束独立生效 | 不能用推测悄悄改变用户风险限制 |
| 股票与期货共享研究流程，资产口径分开 | 合约、夜盘、交割和保证金无法套股票字段 | 期货先选少量品种实际验证，再扩大覆盖 |
| 网页优先，渐进可安装与离线 | 同一套体验覆盖多端 | 系统通知和离线写入需逐平台验证 |
| 业务创建去重、更新做版本冲突 | 断网与多端并发不制造重复或覆盖 | 用户需要看到冲突、未知与未保存状态 |
| 云端运行，Mac 主导工程变更 | 电脑离线不影响提醒，人工仍能介入 | 必须有租约、变更仲裁和单一发布写者 |
| 模型按用途、数据与预算路由 | 小模型可做有限任务，敏感内容不乱发 | 每个提供方独立测试，不做隐式失败切换 |
| 先做受限运维观察与诊断 | 提供透明度，同时缩小公网攻击面 | 交互终端进入独立私有入口，不是普通页面组件 |
| 开源应用、私有 ops、秘密与数据不进 Git | 保持可移植性和个人环境隐私 | 维护两类仓库与独立恢复材料 |
| 交付按真实旅程分批，不整站大爆炸 | 用户能逐步使用，失败可定位、可恢复 | 需要维护一段时间的新旧映射和兼容测试 |

## 本轮明确推翻的假设

不再把“所有功能都进同一侧栏”“所有问题都产报告”“历史越多就更可信”“股票参数适用所有资产”“Agent 生成文字就是动作成功”“页面有控制台就已掌控云端”作为设计前提。

## 独立审视结果

本轮只读交叉审视确认两项必须先解决的问题：当前知识检索只有账号范围，不能直接给 Work 复用；旧 Service Worker 更新会导航所有窗口，会中断任务 / 会议编辑。前者以暂不开放 Work Agent 和后续权限迁移解决，后者在新工作区上线前取消强制导航并验证草稿与更新流程。

再次交叉审视补齐三项合同：研究质量、画像和反馈可见性与 Work 并行交付，不被完整办公功能阻塞；风险校验需要实际组合与市场快照，缺输入返回未评估；研究转任务采用逐项预览和两端鉴权的显式交接，不能通过复制链接扩大检索权限。这些是目标设计补正，尚未声称相关能力已经实现。

暂缓团队资源排期、全量双向日历、向量数据库强依赖、强制 PostgreSQL 迁移和无人值守生产自发布。暂缓是交付顺序，不是永久不做；实际需求与验收成熟后更新本表并说明取舍。
